# 虚拟支付上线清单（D113b）

> 这份文档回答一个问题：**从「代码已就绪」到「真的能收到钱」，还差哪几步、谁来做。**
>
> 结论先说：代码侧**已全部就绪**（下单 / 签名 / 回调 / 查单 / 发货 / 限额 / 降级）。
> 剩下的两步是 **账号级操作**，只能由你本人登录微信后台完成 —— 任何 Agent 都代劳不了，
> 因为它需要法人身份证、对公银行卡、管理员扫码签约。
> 本文档把这两步做成**逐字可复制的表格**，照着填即可。

---

## 一、开通前置条件（必须全部满足）

| 条件 | 本项目状态 | 说明 |
|---|---|---|
| 小程序主体为**企业 / 事业单位 / 个体工商户** | ✅ 已有企业主体 | 个人主体仅「工具」类目可开通，且全终端月限额 10 万元 |
| 已完成**微信认证** | ⬜ **待你操作** | 未认证则 MP 后台看不到虚拟支付入口 |
| 已完成**小程序备案** | ⬜ **待你操作** | 备案未完成同样不出现入口 |
| 服务类目匹配（文娱 / 教育 / 工具 / 社交等） | ⚠️ **需确认** | 类目不对 → 后台**不显示**虚拟支付入口（不是报错，是根本没有菜单） |
| 主体无严重违规处罚记录 | ✅ 默认满足 | —— |

**准备材料**：营业执照、法人身份证、提现银行卡（个体户用法人卡 / 企业对公卡）、支付管理员信息。

---

## 二、MP 后台开通流程

登录 <https://mp.weixin.qq.com> → 左侧栏【**支付与交易** → **虚拟支付**】→【**开通**】。

1. 阅读并勾选签署《虚拟支付服务协议》
2. 提交主体资料：营业执照 / 法人身份证 / 提现银行卡 / 支付管理员信息
3. **账户验证**：支付管理员**是法人** → 可跳过；**非法人** → 需账户打款验证
4. 管理员微信**扫码签约**
5. 等待平台审核：约 **1–7 个工作日**
6. 审核通过后自动生成**虚拟支付二级商户号**（独立于普通微信支付商户号，两者不可混用）
7. 再等约 1–2 个工作日进入商户管理模块

### 开通后要记下的 3 个参数

| 参数 | 是什么 | 在哪找 |
|---|---|---|
| **AppID** | 小程序的身份证号 | MP 后台 → 设置 |
| **OfferID** | 你的支付账号 | 虚拟支付 → 基本配置 |
| **现网 AppKey** | 支付密钥（另有**沙箱 AppKey** 一套） | 虚拟支付 → 基本配置 |

⚠️ `env` 决定用哪一套 AppKey：`env=0` 正式 → 现网 AppKey；`env=1` 沙箱 → 沙箱 AppKey。用混必失败。

### iOS 端额外前置条件

必须配置「**小程序简称**」（Apple 支付需展示 display name）。
入口：mp.weixin.qq.com → 虚拟支付 → 基础配置；配好后回到「基本配置」开通苹果 IAP 支付。
未配简称 → iOS 端开不了 Apple 支付。

## 三、道具申报表（4 个，逐字复制到后台「道具管理」）

**唯一事实源**：`data/goods.js`。前端 `utils/payment.js` 与服务端 `server/index.js` 都 require 它，
**两处都不再各写一份价格**（漂移即 -15013 / 显示价≠实付价）。validate §64.11 机械守卫这一点。

| # | 道具 ID（productId） | 价格（分） | 价格（元） | 道具名称 | 发货内容（give） |
|---|---|---|---|---|---|
| 1 | `tib_lamp_1` | `100` | ¥1 | 点一盏酥油灯 | `lamp` |
| 2 | `tib_blessing_3` | `300` | ¥3 | 送一句藏文祝福 | `blessing` |
| 3 | `tib_khata_6` | `600` | ¥6 | 献一条哈达 | `khata` |
| 4 | `tib_name_99` | `990` | ¥9.9 | 为 TA 取一个藏族名字 | `name` |

**注意**
- 道具 ID **区分大小写、逐字一致**；改一个字符就是另一个道具（未发布 → 报 `-15010`）。
- 价格单位是**分**，`990` 是 ¥9.9，不要写成 `9.9`。
- 后台发布后约 **10 分钟生效**；刚发布就下单会报 `-15014`。

## 四、服务端环境变量（部署时填）

服务端全部走环境变量，**不进代码库**（validate §64 会扫描禁止硬编码密钥）：

| 变量 | 含义 |
|---|---|
| `WX_APPID` | 小程序 AppID |
| `WX_APPSECRET` | 小程序 AppSecret（换 openid 用） |
| `WX_OFFER_ID` | 虚拟支付 OfferID |
| `WX_APPKEY_PROD` | 现网 AppKey（`env=0`） |
| `WX_APPKEY_SANDBOX` | 沙箱 AppKey（`env=1`） |
| `WX_ENV` | `0` 正式 / `1` 沙箱（**现网只能是 0**，否则 -15011） |
| `PORT` | 监听端口，默认 8787 |

回调地址填在后台「消息推送回调地址」，**必须公网可访问的 HTTPS** —— 不可达则不会自动发货
（本项目有查单兜底：前端轮询 `queryOrder`，官方也建议服务端每 5 分钟主动查一次）。

---

## 五、上线三步验收

1. **沙箱**：`WX_ENV=1` + 沙箱 AppKey，走完「下单 → 支付 → 回调 → 发货 → 查单」全流程；
   重点看发货**幂等**（同一单号重复回调不应重复入账）。
2. **现网小额**：`WX_ENV=0`，用 ¥1 的酥油灯真实付一次，确认收礼箱出现一条、灯火 +1。
3. **限额**：确认服务端三条限额生效（同一对好友 3 次/天、单人收 50 份/天、单账号 ¥50/天）。

## 六、错误码速查（来自 utils/payment.js#ERR，照官方文档抄）

| 码 | 含义 | 该怎么办 |
|---|---|---|
| `-15002` | 订单号重复 | 换新单号重试 |
| `-15005` | 用户态签名错误 | 服务端 `signature` 算错，查 session_key |
| `-15006` | 支付签名错误 | 服务端 `paySig` 算错，查 AppKey / env |
| `-15007` | session_key 过期 | 需重新 `wx.login`（本项目已带 code） |
| `-15010` | 道具 productId 未发布 | 去后台「道具管理」发布 |
| `-15011` | 现网版本 env 只能是 0 | 改 `WX_ENV=0` |
| `-15012` | 米大师失败导致关单 | 换新单号重试 |
| `-15013` | 道具价格与后台不一致 | 以 `data/goods.js` 为准核对后台 |
| `-15014` | 道具发布未生效 | 等约 10 分钟 |

## 七、边界（如实说明）

- **代码能做的都做完了**：下单前限额、DB 主键幂等、弱确认→查单、未配置优雅降级、三条红线机检。
- **代码做不到**：微信认证、备案、虚拟支付开通与签约、后台道具发布 —— 都需要你的主体身份与扫码。
- **未配置时不会假装有支付**：`payment.isReady()` 为 false，礼物页显示「祝福通道还没开通」且按钮禁用。
