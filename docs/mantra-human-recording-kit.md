## 一、现在为什么是错的（已核对事实，不是猜测）

| 项目 | 实际情况 | 证据 |
| --- | --- | --- |
| 点灯播的音源 | `audio/voice/mantra.mp3` | `pages/index/index.js:427` → `audio.speak('mantra')` |
| 跳窗播的音源 | `audio/voice/mantra_4x.mp3` | `pages/index/index.js:268` → `audio.speak('mantra_4x')` |
| 藏文文本 | **正确**，就是六字真言 | `scripts/tts-manifest.json`: `text=ཨོཾ་མ་ཎི་པདྨེ་ཧཱུྃ` |
| 声音来源 | ❌ **天翼 TTS 机器合成** | `voice=zhuoma`, `speechRate=0.7`, `dur=2.082` |
| 4 遍版怎么来的 | 由单遍**复制 4 份**拼接（150ms 间隔） | `scripts/gen_mantra_4x.py`，`note` 字段有记录 |

**结论：文字没错，错在「念」**。机器合成按藏文字形拼读，把 ཨོཾ 与 ཧཱུྃ 这类
带**鼻音符号（ཾ / ྃ）+ 下加元音（ཱུ）**的梵音咒字念坏了。这是最典型的
「机器念不好的音」，靠调TTS 参数（语速、音色）不可能修好，只能换人声。

## 二、包体够不够（真实数字，不是估计）

## 三、你要做的（只有一步）

### 录一个文件

- **文件名**：`mantra.mp3`（WAV / M4A 也行，后续统一转 MP3）
- **内容**：ཨོཾ་མ་ཎི་པདྨེ་ཧཱུྃ —— **只念 1 遍**
- **时长**：2~3 秒自然长度，不要刻意放慢
- **环境**：安静房间，手机录音机即可
- **手法**：正常念，**念 2~3 遍**，把最自然的那遍留下（或三遍都发来，我挑）
- **留白**：录音前后各留 1 秒空白，方便裁剪

### 放置位置

```

```

⚠️ 放之前请把**现有 TTS 版改名备份**为 `mantra.tts-backup.mp3` 放到

这样万一要回退，随时能换回来。

## 四、我接手后跑的 4 条命令（你不用管）

```bash
# 1. 体检：确认「真的有声」，不是空文件
python scripts/check_voice.py mantra

# 2. 统一压缩到项目口径（16kHz 单声道 MP3）
python scripts/compress_voice.py --force --bitrate 16k --only mantra

# 3. 用新单遍重拼 4 遍版 —— 这一步自动验证「真的拼了 4 遍」
python scripts/gen_mantra_4x.py

# 4. 全量门禁（1628 项）+ 重建 H5 体验版
node scripts/validate.js
node scripts/build-h5.js
```

第 3 步脚本自带三重校验，任一不过会**直接失败退出**（而不是产出假货）：
- 单遍有声段数 × 4 vs 实际段数（低于 75% 即报错）
- 总时长 ≥ 6 秒
- 峰值有效

第 4 步的门禁 §59.22 还会复核：`mantra_4x / mantra` 时长比 ≥ 3.5（防「被压缩着念」）、
两侧（H5 + 小程序）都播 `mantra_4x`。

## 六、一个诚实的提醒

如果你的六字真言是**按宗教仪轨的唱诵法**念的（带气声、拖长音、每音节有
特定韵律），那请**照你平时的念法录**，不要为了「短」而念成念珠式短音——
那才是正宗的。这个项目的定位是真藏文化，音的**正统性**优先于文件大小。

若你更方便录成一段连念 4 遍的（约 8~10 秒）版本，也可以——
