# 双轨设计（D152）：纯游戏 vs 文化学习

> 结论：**不是二选一，是分轨。** 同一套配对引擎，两条规则不同的轨。
> 纯游戏轨把「好玩」做到位；文化学习轨把「认字」做到位。两条线共用引擎与视觉语言，但**不共用规则、不共用进度、不共用指标**。

## 为什么必须分轨

同一套 6×6 配对机制，被同时要求做两件互相冲突的事：

| 目标 | 纯游戏要的 | 文化学习要的 |
|---|---|---|
| 牌色 | 颜色是线索，越快越好 | **颜色不能泄露答案**，否则不用认字 |
| 步数 | 紧、有压力、可重玩 | 容错、别劝退 |
| 成功判定 | 配对成功 = 赢 | 配对成功 **≠** 认字 |
| 节奏 | 连击、星级、短局 | 复习、文化卡、长线 |

把两者塞进一个模式，必然出现：**颜色即答案**、**配对率冒充识认率**、步数要么太松要么太紧。
实玩已经验证：150 关 0 失败、L1-1 23 对给 58 步；而学习有效性无法用配对率证明（Q1 无提示测验才是）。

## 两条轨

| 维度 | 纯游戏轨 | 文化学习轨 |
|---|---|---|
| 入口 | 朝圣天梯 10 关（三消） | 学习体系 150 课（配对） |
| 牌色 | 彩色（元素本色） | **统一墨色 `#2C3E50`**（D152） |
| 字色 | 浅色 `#FFF6DC` | 浅色 `#FFF6DC`（墨底浅字） |
| 步数 | 三消目标/步数（独立，未动） | 对数 × **1.8**（D151） |
| 内容 | 三消 + 星级 + 连击 + 揭图 | 30 辅音 → 拼读 → 词汇/句子 + 文化卡 |
| 进度 | `completedLevels` / `stars`（老线） | `learnDone` / `learnStats`（独立键） |
| 指标 | 通关率、重玩率、星级分布、D1/D7 | 识认率（Q1，n≥30）、课完成率、复习命中率 |
| 判定 | 配对成功 = 游戏成功 | **配对成功 ≠ 认字**；认字看 Q1 |

## 命名约束（教育类目红线）

玩家可见文案**不得**出现「闯关 / 关卡 / 通关 / 单个『关』」——
`scripts/validate.js` §37 的 `FORBIDDEN37` 与单字量词判定会直接判红。
所以首页入口写「**练习模式 · 10 课**」，**不写**「闯关（纯游戏）」。
若必须用原词，先改类目/红线并在 `DECISIONS` 里明确承担审核风险；
**不能靠改测试绕过**（那是假绿）。

**定稿（2026-10-23，A）**：保留「练习模式 · 10 课」。不在小程序玩家文案中写「闯关/纯游戏」；
将来若做独立游戏版，另立产品/类目，不在本小程序内改词。

## 不做什么

- **不合并两条线的进度**（曾发生 1..150 写进 `completedLevels` 的事故）。
- **不把学习线的配对成功率当识认率**（Q1 才是；提示题不计入）。
- **不把游戏线的颜色也去掉**（那是另一个产品，不是这个）。
- 不为「统一」而统一：两条线的成功判定本来就不同。
