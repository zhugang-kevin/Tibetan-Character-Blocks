## 0. 结论先行

你给的三个解法，**方向都对**，其中两个在合规上比你上一版更进一步（非价格让利、不赚佣金）。但它们落到小程序里还有 9 处会踩雷，其中 **3 处是硬雷**（必须改才能上线）：

| 优先级 | 问题 | 为什么是雷 | 替代（本文 §2 详述） |
|---|---|---|---|
| 🔴 硬雷 1 | 「每核销一单，**商家给我发** 100 个虚拟金币/道具」 | 虚拟币/道具是**平台发行的**，商家发不了；商家若能花钱买它 = 虚拟币与法币双向兑换 → 预付卡/代币口径 + 赌博风险 | **反过来**：核销 N 笔 → **平台**给用户发道具，商家侧**零计酬** |
| 🔴 硬雷 2 | 首次进入「**弹窗**询问常驻/旅行」+「根据 **GPS 定位**默认推荐」 | ① 位置接口在内容/教育类目**拿不到**，且"按位置推商家"是高危驳回点；② 弹窗打断与你此前明确反对的「不弹窗」约定冲突 | **内嵌引导卡 + 城市主动选择**（已实现） |
| 🔴 硬雷 3 | 「挂着卖展示位 / 广告曝光费」 | 小程序内为他人发布推广 → 可能被认定**广告经营**（执照需含广告发布）；《广告法》要求可识别 | 改「**文化联名合作**」（联名文化卡 / 联名印章 / 联合署名），内容形态、不需广告资质 |
| 🟠 需处理 | 「**积分**换本地超市小福利」 | 平台定价 + 平台兑付 = 平台在**发行有价凭证**，把 v2 刚关掉的门又打开了 | 积分不新增：**通关关数本身就是门槛**，兑换动作 = 发凭证 → 商家店内兑现 |
| 🟠 需处理 | 「曝光位换 100 张甜茶福利」 | 以物易物 = **视同销售**，双方都要确认收入并开票 | 合同化 + 双向开票，别当"没花钱就不用记账" |
| 🟠 需处理 | 「凭游戏**通关截图**」享权益 | 截图可转发、可伪造、**无法限领次数** | 券码 + 一次性 token + 绑 `openid` + 限领 1 次 |
| 🟠 需处理 | 「**免排队特权**」 | 易被投诉为插队权 | 「视门店客流，优先安排」，不承诺 |
| ⚪ 已知 | 「门票绑实名 / 用户画像给商家」 | PIPL §23；小程序无公开实名接口 | 已有替代（v2 §2.6），本文不重复 |
| ⚪ 边界 | 布达拉宫 / 大昭寺等**宗教活动场所与景区** | 宗教场所不得商业联动；景区门票不是你的标的 | **只对接周边经营主体**；自检脚本硬拦（validate 16.3） |

**一句话记法**：你方案里所有的钱，最终都要能回答一个问题 —— **「这笔钱是谁付给谁的？」**
只要答案里没有「用户 → 你 → 商家」，就都是安全的。

## 1. 三个问题的解法（采纳 + 加固）

### 问题 1：本地人和游客需求完全错位 → 双轨制权益体系 ✅ 采纳

你的设计完全正确，我做了三处产品化加固：

| 你的原设计 | 加固后 | 为什么 |
|---|---|---|
| 权益中心顶部做分类 Tab | **Tab 常驻顶部**，且首次进入用**内嵌引导卡**让用户先选一次；选完记住（`userMode` 持久化），下次不再问 | 弹窗会打断；引导卡同样显眼，还不违反「不弹窗」纪律 |
| 弹窗问「您常驻哪里 / 是来旅行吗」 | 改问「**你想看哪一类**」（本地生活 / 游客专属） | ① 不收集身份信息（PIPL 最小必要）；② 回答负担更低；③ 本地人也能给来访的朋友看游客券 |
| 根据 GPS 定位默认推荐 | **城市由用户主动选**（拉萨 / 林芝 / 日喀则 / 山南） | 位置接口拿不到；且**主动表达目的地 = 真实出行意向**，比被动定位更值钱 |
| 后台给商家打标签 | **`track: local / tourist / both`** 三值；`both` 两端都可见 | 甜茶馆、文创店、邮局这类对本地人和游客都成立，硬二分反而漏商家 |
| 本地券做「满减」 | 券面**只写商家的到店权益**，不写平台承诺的金额 | 见 §2「最难的一条」 |

### 问题 2：商家凭什么打折 / 不缺流量怎么办 → 谈增量，不谈打折 ✅ 采纳

你的 A / B / C 三个方案是这轮里最扎实的部分，我原样保留并补了话术边界：

| 方案 | 你的设计 | 加固点 |
|---|---|---|
| **A 专属附加价值** | 甜茶馆送 5 元点心（成本 1.5 元）、唐卡馆送藏纸书签 | 别写「价值 5 元」到券面上 —— 写「赠藏式甜点一份（店内自制款）」。**价值由商家口头说，不写进平台凭证** |
| **B 游戏专属套餐** | 原价 35、专属价 28 的定制套餐，平时不卖 | 套餐名要落在店内可执行的位置（收银系统 / 菜单临时贴纸）；建议**只在店内兑现，平台不做核销金额记录** |
| **C 非价格福利** | 免排队、优先选座 | 文案统一加「**视门店客流 / 视房态**」（已在数据里做） |

**给商家的话术**（你的原话，稍微收紧一处）：

> 「老板，我不要求你降价。你原本给 OTA 的展示费省下来，我这边给你**曝光与到店机会** —— 你只需要给用户一个**游戏专属的小福利**（一杯甜茶、一个靠窗位）。」
>
> ⚠️ 把「我给你导流」改成「**我给你曝光与到店机会**」—— "导流"隐含效果承诺，宣传语里容易变成把柄。

### 问题 3：我引流、商家给折扣，还会给我佣金吗 → 不赚佣金，赚三笔 ✅ 采纳（其中一笔改造）

## 2. 详细设计：双轨制权益体系

### 2.1 它不是两套系统，只是一个标签

```
商家 ── track: local | tourist | both ──┐
                                        ├──→ 按用户所选模式过滤 ──→ 券列表
用户 ── userMode: local | tourist ──────┘
             + city: lhasa|nyingchi|shigatse|shannan
```

**「一键切换」的价值不在技术，在于它把"运营"变成了"用户自己选"。** 你不需要猜用户是谁，让用户自己告诉你要看什么。

### 2.2 领取门槛 = 通关关数（这是整条闭环的枢纽）

| 门槛来源 | 是否新增系统 | 是否产生资金流 | 结论 |
|---|---|---|---|
| 新增「积分」体系 | 是（要算分、要定价、要兑付） | **会** → 有价凭证风险 | ❌ 不做 |
| **通关关数（`need`）** | 否（已有 `completedLevels`） | **不会** | ✅ 采用 |

```
一关都不过  → 只能领 need=0 的「见面礼」（雅砻河谷甜茶馆赠甜茶 / 高原邮局明信片）
通关 1 关   → 解锁茶馆点心、藏面专属组合、联名印章
通关 2 关   → 解锁超市购物袋、唐卡书签、藏香体验装
通关 3 关   → 解锁民宿延退、旅拍精修
```

**为什么这样最好**：它把「玩游戏」直接变成权益货币，**不需要发明新积分、不需要给积分定价、不产生任何资金流** —— 三个风险一次性归零，而用户的动机一点没少。

### 2.3 券的生命周期与三层核销

```
领取(claimed) ──→ 到店核销(used)
      └────────→ 过期(expired)          ← 状态锁定后不可逆
```

| 层 | 形态 | 适用商家 | 实现 |
|---|---|---|---|
| 主 | 商家在本小程序内切角色扫码 | 会用小程序的商家 | `openid` 白名单 + `wx.scanCode` |
| 备 | **一次性核销链接**（点开即确认） | 甜茶馆、老人店 | 一次性 token（TTL 5 分钟 + 绑商家 ID + 用后即焚） |
| 冷启动 | 人工代录 + 纸质签单 | 首 1-2 家验证期 | 后台录入 |

> 本期已实现的是**用户侧凭证与码**（本地流水 `ZW0001`）；核销端需要后端，属下一期。

### 2.4 合规定性：为什么「券不承载金额」是全文最关键的一句

这是最难的一条，因为你的本地生活设计里天然有「满减券」。调和办法是**区分主体**：

| 谁在承诺 | 定性 | 判断 |
|---|---|---|
| **平台**在券面写「满 100 减 20」并保证兑付 | 平台在**发行有价凭证**；可变现/可充值 → 二清 / 单用途预付卡口径 | ❌ 不做 |
| **平台**写「凭此凭证到 XXX 店解锁专属体验」，到店后商家按**自己的店内促销**给优惠 | 平台只证明"该用户完成了学习任务"，**不承诺任何金额或折扣**；商家给什么是商家的经营自主权 | ✅ 采用 |
| **商家**自己在店内做满 100 减 20 | 商家自己的促销，与平台无关 | ✅ 可以（券面不写） |

一句话：**平台是"凭证发放方"，不是"优惠券发行方"。**

已在代码里**机械保证**：`scripts/validate.js` 第 16.2 节会扫描 `data/merchants.js`，出现 `¥` / `元` 字样或 `price/amount/discount/settle` 字段（**含 `discountRate` / `maxDiscount` 等变体**）**直接判错**；第 25 节把同一把尺子量到**页面层**（见 2.4.1）。每张券卡强制渲染一句 `由商家自主提供并兑现 · 藏字方块不参与交易、不收取任何款项`。

#### 2.4.1 折扣一定要用百分比吗？（2026-10-05 · D28）

外部方案提出「固定金额券是死路 —— 所有优惠权益统一用百分比折扣」。**前半句对，后半句对本项目不适用。**

| 命题 | 核对 |
|---|---|
| 固定金额券在低价商品上必然倒贴（满 10 减 10 撞 5 元商品 → 实收 **−5**） | ✅ **数学正确** |
| 「所以券面应该改印『9 折』」 | ❌ **不成立**。平台印出任何**可计算的让利**（金额或折扣率），都等于替商家承诺价格 —— 上面那句「不参与交易、不收取任何款项」会立刻自相矛盾。**写「9 折」与写「满 100 减 20」在法律定性上是同一件事，只是数值不同** |

所以本项目对这条原则的采纳方式是**否定式**：

> **券面既不写固定金额，也不写折扣率。让利由商家在店内自己贴 —— 那是商家的经营自主权。**

**字段契约留档**（备「商家核销端」D13 解禁后使用，**现在不落任何数据文件**）：

| 字段 | 定义 | 约束 |
|---|---|---|
| `discountRate` | 折扣率，归一化 **0–1**（`0.9` = 9 折） | 只存在于商家自己的账里；**不得进入 `data/*.js`**（§16.2 判错） |
| `maxDiscount` | 最高抵扣金额，可选（`null` = 不限） | 同上 |
| 核销口径 | `实收 = 原价 × discountRate`，再对 `maxDiscount` 取小 | 这是**商家**的账，不是平台的账。平台收入是 D17 的「**定额 × 核销笔数**」 |
| 前端渲染 | 若将来商家侧确实要显示，只渲染「9 折 / 10% off」，**永不渲染固定金额** | 且必须由**商家自己的后台**渲染，不经平台数据层 |

**已否决（不要回退）**：

- ❌ **按商家类型定折扣梯度**（甜茶馆 9-9.5 折 / 藏餐 8.5-9 折 / 体验馆 8-8.5 折 / 民宿 9-9.5 折 / 文创店 8.5-9 折）—— 平台替不同行业商家定折扣 = **平台定价 = 变相发行有价凭证**，撞 D15 / D16；
- ❌ **稀有度四档映射折扣**（普通 9.5 折 / 稀有 9 折 / 史诗 8.5 折 / 传说 8 折）—— 把玩法稀有度变成价格让步，**机制沦为折扣发生器**；
- ❌ **燃灯祈福换折扣券**（1 盏 → 9.5 折 / 连点 7 天 → 9 折 / 连点 30 天 → 8.5 折）—— `utils/lamp.js` **刻意零奖励**（D24）；祈福是非交易性仪式，不兑换任何权益，也不得与商业联动。

**机械保证**：`validate.js` §16.2（数据层，词干匹配 `discountRate` / `maxDiscount` 变体）+ §25（**页面层**：权益中心 4 个文件与体验版区块同样禁让利数字与金额字样；券面文案必须**逐字**来自数据层，页面不得自行拼接）。§16.2c 与 §25.3 是**反例自测** —— 门禁要证明自己拦得住，而不是「碰巧现在干净」。

## 4. 收益模型：不赚佣金，赚三笔（加固版）

| 来源 | 你的原话 | 加固后 | 残留风险 | 何时做 |
|---|---|---|---|---|
| **① 位置 / 曝光** | 「我不抽你佣金，但你店里要挂一个月，用流量换商家的产品」 | 改叫「**文化联名合作**」：联名文化卡 / 联名印章 / 联合署名 + 换取商家福利产品；**置换写进合同并按公允价开票** | 广告经营资质（若真卖广告位）；视同销售的税务处理 | 首家商家即可谈 |
| **② 游戏内道具** | 「商家给我发 100 个虚拟金币」 | **倒过来**：核销 N 笔 → **平台**给用户发道具；商家侧**零计酬** | 虚拟币与法币双向兑换（已回避） | 有核销数据后 |
| **③ 跨区 / 大 B** | 「拿商家数量 + 用户数据去拿文旅局项目、景区广告、政府补贴」 | 保留（**天花板最高**）；但只出**聚合统计**，不给个人信息；政府项目走正规申报与采购 | PIPL §23；政府项目需资质/招标 | 商家数 ≥ 20 后 |

**为什么 ③ 是真正的钱**：单家小商家的利润薄到谈不出佣金，这你已经说对了。但「**已接入 50 家本地商家 + 日均几千次精准藏文化互动**」这个事实，对文旅局、景区、品牌方是另一种量级的商品。**小商家是你的数据来源，不是你的收入来源。**

**并且它解决了一个更深的问题**：收入不再 100% 押在日活上。日活是你能"运营"但不能"承诺"的东西；商家数量是你**能主动推进**的变量。

### 4.1 最终闭环（加固版）

```
本地人：玩小程序 → 看文化卡 → 攒通关进度 → 领本地生活权益（超市/茶馆/理发）
      → 到店核销 → 明天再来（省钱动机驱动复访）

游客：  玩小程序 → 看文化卡 → 攒印章/进度 → 领游客专属权益（套餐/优先位/旅拍）
      → 到店打卡 → 分享朋友圈 → 带来新用户

商家：  提供「非价格让利」（小礼物 / 专属套餐 / 优先权）
      → 换曝光与到店机会 → 零现金支出拿到精准客源

你：    不赚交易佣金（也不碰交易）
      → 换来「商家的福利产品」
      → 做成游戏奖励发给用户（自己不用花一分钱）
      → 拿着「商家数量 + 用户活跃 + 出行意向数据」去谈文旅局 / 景区 / 品牌
```

**一句话定位**：前期的你不跟商家抢利润，你只做**「流量与文化的连接器」**；你要赚的钱在后端（项目合作、政府文旅、品牌联名）。
