# 第一部分 · 初衷

## 1.1 最初要做什么

一个**藏文字母学习工具**：

- 让完全不懂藏文的人，**30 天内认出 30 个藏文辅音字母**
- 用「配对消除」的方式降低学习门槛（比背诵轻松）
- 顺带传播藏族文化好感
- 商业上，通过文化产品（唐卡/藏香/虚拟礼物）转化

## 1.2 定位的三次修正

| 阶段 | 定位 | 谁定的 |
|---|---|---|
| 初期 | 藏文学习小游戏 | 用户 |
| 中期 | **小游戏 → 小程序**（避开版号） | 用户明确 |
| 现在 | **藏文化学习工具 + 文化产品转化** | 用户（D170） |

**D170 是最重要的一次修正**，用户原话：

> 「我们卖的是藏文化相关配饰/装饰艺术，**不是宗教用品**。做的是文化宣传，跟宗教没有关系。」

因此商品标题公式改成 `藏式装饰画 · {题材}题材`，「题材」两个字**不能省** —— 它是文化产品与宗教用品的分界线。

## 1.3 明确的红线（用户反复强调）

- ❌ 不做宗教用品，不做宗教功效宣传
- ❌ 不碰「开光/加持/供奉/保佑/镇宅」这类词
- ❌ 不改游戏核心玩法之外的东西（会打乱既有成果）
- ✅ 数据必须带**来源 + 查询日期**
- ✅ 不知道就说不知道，**不许编**

## 5.2 我们与它们的根本差异

| 项 | 业界 | 我们 |
|---|---|---|
| 玩法 | 交换 + 三连 | **点两张相同（配对）** |
| 盘面 | 8×8 | 6×6 |
| 重力下落 | 有 | **没有** |
| 连锁 | 有 | **没有** |
| 长连奖励 | 有 | **没有** |
| 死局重洗 | 有 | ✅ 有 |

**结论：我们做的不是消消乐，是「连连看/找相同」。**

**这个差异不是 bug，是选择。** 但用户想要的是消消乐的手感 —— 这是当前最大的认知分歧点。

# 第六部分 · 我犯过的错误（全清单）

> **这一节是重点。** 用户要求「一个都不能漏」。
> 按「错误 → 现象 → 根因 → 现在的处理」列。

## 6.1 严重错误（导致用户明确不满）

### E01 · 实物藏香商城方向
- **现象**：花大量时间做实物商城、供货合规、检测报告
- **根因**：把「变现」理解成「卖实物」
- **结果**：D147 用户明确放弃，全部代码删除
- **现状**：已清理，有反向门禁防复发

### E02 · 150 课做完了但玩家看不到
- **现象**：用户反复说「还是停在 10 关」
- **根因**：功能做完 ≠ 界面展示。天梯只有 10 节点，页脚写「共 10 课」
- **现状**：已加 150 格全景图（但配色一度不可见，见 E09）

### E03 · 抠图三连败
- **现象**：想把金底吉祥八宝抠成透明底，试了 3 次，每次都毁主体
- **根因**：**金底与主体同色，抠图必然失败** —— 这是物理事实，我却反复试
- **正解**：用户一句话点破「直接当背景」，一次就成
- **教训**：不该钻牛角尖

### E04 · 日签卡设计方向错
- **现象**：第一版做成「米色底 + 细金线 + 现代排版」，用户判定「垃圾」
- **根因**：没有参考藏文经卷的实际形态
- **现状**：重做成红底金框 + 镶宝圆点，用户认可

### E05 · 图片重叠（长明灯弹窗）
- **现象**：弹窗里两个佛像叠在一起
- **根因**：**同一个 `buddha-bg.jpg` 被引用两次**（卡片背景 aspectFill + 佛龛 widthFix）
- **现状**：已删一层，补暗色渐变兜底

### E06 · 首页 150 格数字看不见
- **现象**：「下面的数字压根就看不到」
- **根因**：`background: rgba(44,62,80,0.06)`（6% 透明）+ `color: #6E6759`（灰字）+ `.lock { opacity: 0.42 }`，压在布达拉宫照片上
- **现状**：改实底 + 白字 + 金边

### E07 · 首页根本不是满屏
- **现象**：手机上是屏高的 1.6–2 倍，必须滚动
- **根因**：`min-height: 100vh`（允许内容撑高）+ `100vh`（iOS 含地址栏）
- **现状**：改 `height: 100dvh`，实测 4 机型溢出全部 0px

### E08 · 盘面只占 40% 高
- **现象**：棋盘挤在上半屏
- **根因**：6×6 **正方形**，宽撑满后高必然等于宽（40%）
- **现状**：**未解决**。加了进度条（30px），但根本解法是加 HUD 或改盘面形状

### E09 · 反馈挂在连击上，新手全程无声
- **现象**：「东敲西敲没一点反应」
- **根因**：震动/音效/光晕**全部挂在 `combo tier` 上**，新手连不成 → 零反馈
- **现状**：已给单次配对加三件套（**未真机验证**）

### E10 · 客服页是孤岛
- **现象**：客服页面写好，全项目**没有一处跳转**到它
- **根因**：只做了页面，忘了入口
- **现状**：已在 passport 页加「联系客服」入口

## 6.2 方法错误（不致命但浪费大量时间）

### E11 · 改错地方：一直在改 H5 镜像
- **现象**：改了半天 H5，用户玩的是小程序
- **根因**：H5 是我自己的测试工具，不是交付物。**忘了这一点**
- **教训**：改之前先确认「用户看的是哪个」

### E12 · stripComments 连错两次
- **第一次**：直接 grep `.wxml` → 报「12 处游戏化词汇」，全是 HTML 注释
- **第二次**：只删整行 `//`，漏了行尾注释 → 仍报 12 处
- **第三次**：删 `//[^\n]*` → 真正 **0 处**
- **教训**：**「扫描到问题」前必须先证明扫描方法可靠**

### E13 · 误判「文件被我改坏了」
- **现象**：只看 `grep -c 小程序码 = 9` 就宣布文件损坏，让用户差点回退
- **真相**：`git diff` 显示 9 处都是**合法引用**，文件没坏
- **教训**：**「数量异常」≠「文件损坏」，要看 diff**

### E14 · Python 脚本批量改大文件
- **现象**：连续三次报告「已改」，其中两次是假的（断言失败但已写盘 / 字符串语法错误）
- **根因**：用 Python 做字符串替换，中间态不可控
- **正解**：**用 Edit 工具做行级编辑，每改一处立刻 grep 验证**

### E15 · 部署文档写错 Node 版本
- **现象**：文档写 Node 20，实际代码用 `node:sqlite` 需要 **Node ≥ 22.5**
- **根因**：凭印象写版本号，没看代码
- **现状**：已改，并加了开跑前校验

### E16 · 密钥写在 systemd Environment 里
- **现象**：`Environment=WX_APPKEY_PROD=xxx` → `systemctl cat` 明文可见
- **现状**：改 `EnvironmentFile` + 640 权限 + `.gitignore` 挡密钥

## 6.3 未来的风险（还没犯，但要防）

### E17 · 只剩「报告」没有「交付」
- **风险**：每次都回「我建议你…」，用户要的是结果
- **对策**：能做的直接做，做完给实测数据

### E18 · 把「模拟通过」当「真实接入」
- **风险**：`supervisor.js` 是模拟器，不能说「自动续跑已实现」
- **对策**：所有状态按五顶口径如实标（见 3.3）

### E19 · 编造数据（寺庙/价格/资质）
- **风险**：150 座寺庙如果编名字和来源，是致命错误
- **对策**：**没有 `source` 字段的条目不入库**

### E20 · 为了「看起来完成」而降低标准
- **风险**：把「加了 CSS 纹样」叫「真实拼图」，把「咨询按钮」叫「电商完成」
- **对策**：文档里明确写「不做什么」（见总设计第五节）

# 第七部分 · 沟通问题的根源（我的自我诊断）

用户说「我们之间相互沟通有问题」，我认同，原因有三：

## 7.1 我在「修症状」而不是「对方案」

- 用户说「棋盘太小」→ 我改 `tileW`
- 用户说「没刺激」→ 我加音效
- 用户说「没藏文化风格」→ 我改配色

**每次都修一处，从没停下来问「整体设计对不对」。** 直到用户逼我写这份文档。

## 7.2 我没有把「用户要什么」和「代码有什么」摆在一起给他看

用户是产品决策者，但他看不到代码。**我应该主动做对照表**（就像 5.2 那张），而不是等他说「你去看 GitHub」。

## 7.3 我报告「已改」时没有给证据

用户没法验证我改了什么。**从现在起每次改动都给：改哪个文件、第几行、validate 数字、实测数据。**
