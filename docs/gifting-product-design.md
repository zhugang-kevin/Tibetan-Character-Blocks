# 打赏产品设计（D89，小程序形态）

> 产品形态已定：**保持「小程序」**。关系链四项（排行榜/提醒/擂台赛/微信礼物）关闭。
> 本文设计**小程序上能落地的打赏**——不依赖任何资质即可定稿的部分；
> 资质与支付接入见 `docs/tipping-implementation-plan.md`。

---

## 一、先定三条不可越的红线

| 红线 | 为什么 |
|---|---|
| **A 不分钱** | 一旦 A 能提现 → 资金二次清算 + 诱导分享，**微信不允许** |
| **不做排行榜** | D6 已拍板无排行榜；且小程序也拿不到关系链 |
| **不做"充值/道具/装备"话术** | D41/D43 去游戏化（教育·文化类目）；且**诱导分享是审核红线** |

**A 得到的是「文化意义上的回响」，不是钱。** 这是这个产品能成立的前提。

---

## 二、B 为什么能看到 A？——只能靠分享链路

**没有关系链** → B 不会"自动知道 A 在玩"。所以打赏的入口**必须挂在分享上**：

| 入口 | 状态 |
|---|---|
| A 分享「挑战卡」给好友/群（带成绩参数） | ✅ **已实现**（D86） |
| A 分享「祝福卡」到朋友圈 | ✅ 已实现 |
| B 从卡片进入 → 看到 A 的成绩 → **「送一份祝福」** | ⬅️ **本文要设计的部分** |
| B 送出 → A 收到（**依赖服务端**） | ⏳ 待服务端 |

**所以链路是**：`A 分享 → B 看到 → B 送祝福 → 服务端记账 → A 收到`。
**没有分享就没有打赏** —— 这不是限制，而是**产品逻辑本身**：祝福要靠人带过去。

---

## 三、礼物设计（贴合文化定位，不是"道具"）

| 名称 | 价格 | B 的动作 | A 得到的回响 |
|---|---|---|---|
| **点一盏酥油灯** | ¥1 | 为 A 祈福 | 灯火 ×1；「万家灯火」总灯数 +1（已有功能 D35） |
| **送一句藏文祝福** | ¥3 | 从 6 句祝福中选一句 | 收到一张**藏文祝福卡**（可保存/再分享） |
| **献一条哈达** | ¥6 | 献哈达 | A 的收藏页出现一条哈达 |
| **藏文名字定制** | ¥9.9 | 输入 A 的名字 → 生成藏文写法 | A 收到**专属藏文名字卡** |

**为什么是这四样**：
- 全部是**既有资产**（酥油灯 / 祝福卡 / 哈达 / 藏文名字），**不需要新美术**
- 全部**文化相关**，与教育类目一致（不是"皮肤/装备"）
- 价格梯度 ¥1 / ¥3 / ¥6 / ¥9.9 —— 门槛低，符合"心意"而非"消费"

---

## 四、A 收到什么（关键设计）

**A 收到的不是钱，而是**：

1. **实物的文化回响**：灯火 +1、祝福卡入收藏、哈达展示、专属名字卡
2. **一句来自朋友的藏文**（B 选的那句，带 B 的昵称）
3. **「XX 人为你点了灯」的记录**（本地收藏页）

**且不设**：
- ❌ 不设「谁送得多」的榜
- ❌ 不设「送满 X 次解锁皮肤」的激励（那是游戏化，与去游戏化冲突）
- ❌ B 送礼后不给 A 任何"特权/加成"（避免"送礼=变强"的观感）

**理由**：我们卖的是**文化祝福**，不是**数值特权**。一旦变成数值，就退回游戏内购的逻辑，
既触碰审核红线，也丢了产品的文化定位。

## 五、防御设计（必须有）

| 风险 | 对策 |
|---|---|
| 刷单/自送自收 | 同一对 B→A 每天限 3 次；单个 A 每天最多收 50 次 |
| 未成年人 | 支付前校验；单账号单日上限 ¥50 |
| 退款纠纷 | 虚拟商品明确标注「不支持退款」（下单页可见）|
| 文案违规 | 全站不得出现「充值/返现/分佣/提现」；打赏页只出现「祝福/心意」 |
| 诱导分享 | **不设**「分享后可得」；分享纯自愿 |

## 六、现在还做不了的部分（如实标注）

| 环节 | 依赖 |
|---|---|
| 真正收款 | 正式 AppID + 微信认证 + 虚拟支付开通（**需你先做**） |
| 签名/下单/回调 | **服务端**（官方：签名只能在服务端算） |
| B 送 → A 收的闭环 | 服务端（跨用户数据） |

**这三件都卡在同一个地方：服务端 + 资质。** 与产品设计无关 —— 设计可以先定稿。

## 七、本设计对现有代码的影响（已核对）

| 已有资产 | 用法 |
|---|---|
| `pages/result` 祝福卡生成 | 复用为「藏文祝福卡」的卡片样式 |
| 「万家灯火」灯火计数（D35 / task #78） | 复用为「点灯」的计数 |
| 收藏页（`pages/passport`） | 承载「收到的祝福」 |
| 挑战分享链路（D86，已实现） | 打赏入口挂在它上面 |
| 藏文子集字体（D83，已内嵌） | 卡片生成时用同一字体，观感一致 |

**结论：打赏不需要新造轮子，是把已有资产串起来 + 接一个支付通道。**
