## 四、我的建议：**不建议一次全录，分 4 批**

理由不是偷懒，是三条硬事实：

1. **一致性风险**：一次录 166 条，中途换状态（嗓子哑了/换环境）会导致  
   音色与响度不一致。更稳的做法是**同一批录完立刻入库、一批一批走完流程**。
2. **包体会顶**：166 条按 16kbps 估≈ 0.4~0.8MB，而主包余量只有 **189.5KB**。  
   → **必须走分包**（`package-praise/` 已有先例，微信标准解法），  
   不能一次全塞进主包。
3. **有Gate 2 需要你裁决**：录完之后要逐条听审才能定稿，  
   这是纯人工环节，必须跟你自己的时间节奏对齐。

### 建议批次

| 批次        | 内容                 | 条数     | 主包影响          | 何时做      |
| --------- | ------------------ | ------ | ------------- | -------- |
| **第 1 批** | B(8) + C(1) + A(9) | **18** | ~50KB，直接放主包   | **现在**   |
| **第 2 批** | E(19) + F(8)       | 27     | ~90KB，可放主包或分包 | 第 1 批定稿后 |
| **第 3 批** | D 上加字 + 下加字        | 73     | 走分包           | 学习体系扩展前  |
| **第 4 批** | D 前加字              | 48     | 走分包           | 最后       |

**第1 批是我强烈建议立刻做的**：18 条、单字为主、包体只增约 50KB、  
而且**一次性消灭「有错音」和「点了没声」两类真实缺陷**。

## 六、我每批接手后跑的流程

```bash
python scripts/check_voice.py <条目>          # 1体检：确认有声（不是空文件）
python scripts/compress_voice.py ...          # 2 统一压缩 16kHz/单声道 MP3
python scripts/gen_mantra_4x.py               # 3 仅六字真言：重拼 4 遍 + 三重校验
python scripts/normalize_voice.py --apply     # 4 响度归一到 -20 dBFS
node    scripts/gen_voice_index.py            # 5 重建 data/voices.js（有新增/移除时）
node    scripts/validate.js                   # 6 门禁全量（现1631 项）
node    scripts/build-h5.js                # 7 重建 H5 体验版
```

**门禁会替你守住的质量底线**（不会因为换了音源而放松）：

- 有声判据：时长 ≥0.25s、峰值 > −32 dBFS、单声道 16kHz
- 六字真言4 遍：段数 = 单遍×4、总时长 ≥6s、时长比 ≥3.5
- 包体上限：`node scripts/validate.js` 红则不通过
- 「待录入」清单与实际目录一致性（漂移即报错）
