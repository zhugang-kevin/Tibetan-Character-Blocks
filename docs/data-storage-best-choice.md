## 二、三个「免费」方案的真实限制（都是官方原文）

### 2.1 微信云开发 —— ❌ **假免费**

官方计费说明原文：

> 「新用户可免费体验一个与基础套餐配额相同的环境，体验时长为六个月。」
> **「免费云环境在小程序发布后，环境的到期时间变更为上线后的第 15 天。」**
> 「若需长期使用，则需要将免费环境转为付费环境。」

- **即：开发阶段免费，一上线 15 天后就必须付费**
- 基础套餐：**19.9 元/月**（原价 39，5 折），配额 调用 20 万次 / 容量 2GB / QPS 500
- 按量：调用 0.5 元/万次、容量 0.1 元/GB/日
- **结论：这不是免费，是「上线 15 天后开始收费」，而且**一绑定就换不掉（数据人质）

### 2.2 Supabase Free —— ✅ 无期限，但有个对小程序致命的问题

官方定价页与文档（第三方核对至 2026-08）：

| 项 | 免费额度 |
|---|---|
| 价格 | **$0，无时间限制**（是真正的免费层，不是试用） |
| 数据库 | **500 MB**（超过进**只读模式**；注意是「数据量」不是磁盘） |
| 磁盘 | 1 GB（WAL 与系统文件不占额度） |
| 带宽 | **10 GB**（官方文档明确：5 GB cached + 5 GB uncached） |
| MAU | 50,000 |
| **闲置** | **连续 7 天无流量 → 暂停，需手动恢复** |
| 项目数 | 2 个（跨组织统计） |

**致命问题**：**「7 天无流量自动暂停」对小程序是灾难** ——
用户第 8 天打开，数据服务是停的，必须你手动去后台恢复。
这不是理论风险：第三方同一份核对里写得很直白，这是「离开免费层最常见的原因」。

### 2.3 WorkBuddy 云服务 —— ✅ 真好用，但**装不进包**

- 已开通（`billingStatus=normal` / `provisionStatus=assigned`），零费用
- 底层是**托管 PostgreSQL + PostgREST**（supabase-js 兼容），有 RLS 隔离
- **阻断**：SDK 的小程序产物 **507 KB 单文件**，而主包只剩 **6 KB** 余量 ——
  硬塞 → **2359 KB > 2048 KB 硬上限 → 上传必失败**（D93 实测）

## 五、代价（如实说清）

**自建比托管方案少的东西**：**没有数据库层强制的 RLS**。

- 托管方案：RLS 策略写进数据库，**即使前端代码写错也越不了权**
- 自建方案：隔离靠**服务端的查询条件**（`WHERE openid = ?`），**依赖代码写对**

**如何把这个差距补上**（我会在实现里做）：
1. 服务端**不信任客户端传来的 openid** —— 用 `code2Session` 从微信换，客户端无法伪造
2. 所有读写**强制带 openid 条件**（不提供「按 id 查任意行」的接口）
3. 门禁加一条：**同步接口的 SQL 必须含 openid 条件**（机器可查，不靠人记得）
