> 目的：把「业界怎么做」和「我们现在怎么做」摆在一起，供决定用哪个范式

## 二、核心规则的业界共识

### 2.1 交换

```
① 点第一张 → 高亮/放大（视觉反馈）
② 点相邻一张 → 尝试交换
③ 交换后**必须能成线**，否则交换回弹，不扣步数
④ 能成线才真的换位置，并消耗一步
```

**关键点**：`k228/candy-crush` 里有一个独立函数 `isAdjacent()` ——
**只允许上下左右，不允许斜向。**

### 2.2 匹配判定

```js
findMatches()  // 横向扫一遍 + 纵向扫一遍，找 3+ 连续同色
removeMatches() // 标记为 null，不是立刻删除
collapseTiles() // 从下往上，把非 null 下落填满
refillGrid()    // 顶部补新块
// 然后**递归**再跑 findMatches —— 这就是连锁（cascade）
```

**顺序不能乱**：标记 → 下落 → 补牌 → 再判定。

### 2.3 计分（`dianadeliz` 的实现）

| 匹配长度 | 分数 |
|---|---|
| 3 连 | 每块 10 分 |
| **4 连** | **额外 +20** |
| **5 连及以上** | **额外 +50** |

**这就是用户说的「敲对两个四个爆破」** —— 长连有额外奖励，是品类的核心爽点。

### 2.4 关卡目标

| 实现 | 目标 | 步数 |
|---|---|---|
| MisterCoder74 | 分数（1000/2000/3000/5000/7500）| **30 步** |
| dianadeliz | 每 100 分升一级 | 不限 |
| k228 | 纯计分 | 不限 |

### 2.5 死局处理

**五份代码里有三份明确写了「无合法交换时重洗」**（`reshuffle` / 检测 `hasValidMove`）。

## 三、我们现在是什么

| 项 | 业界 | 我们 | 差 |
|---|---|---|---|
| 盘面 | **8×8** | **6×6**（学习线）| ❌ 小两号 |
| 交换 | 点选 → 点相邻 → 判定 | **没有交换** | ❌ **完全没有** |
| 匹配 | 3+ 连线（横/竖） | **点两张相同** | ❌ **范式不同** |
| 消除后 | 下落 + 顶部补新 | **原地消失，不下落** | ❌ 没有重力 |
| 连锁 | 递归直到稳定 | **无** | ❌ 没有 cascade |
| 长连奖励 | 4连+20 / 5连+50 | **无** | ❌ 没有爽点 |
| 死局 | 检测 + 重洗 | **有重洗**（`reshuffle`，池感知）| ✅ 这项有 |
| 步数 | 30 步/关 | 13–16 步 | ⚠️ 偏少 |

**结论：我们做的不是消消乐，是「连连看 / 找相同」。**

## 四、为什么 6×6 只占屏 40% —— 几何原因

```
手机 390 宽 × 844 高
6×6 正方形盘：宽撑满 335px → 高也是 335px → 335/844 = 40%
8×8 正方形盘：宽撑满 335px → 高还是 335px → 还是 40%
```

**换成 8×8 也不能解决纵向占比** —— 因为**正方形放进竖屏，高度必然等于宽度**。

**真实消消乐怎么解决**：盘面本来就不该占满全屏。
它们上下是 **HUD**（关卡目标 / 分数 / 步数）、**道具栏**、**目标卡片**。

**所以我们真正缺的不是"把盘面拉大"，是"盘面之外那些东西"。**

## 五、三条路线（代价差很大）

### 路线 1：改成真三消（对齐业界）

| 要做 | 影响 |
|---|---|
| 6×6 → 8×8 | **150 课的关卡数据全改** |
| 加交换交互 | 新增手势 + 回弹动画 |
| 加下落 + 补牌 | 重写渲染层 |
| 加连锁判定 | 新增递归逻辑 |
| 加长连奖励 | 改计分 |
| **关卡指纹重算** | **`test-level-guard` 全部要 `--update`** |

**这是重做游戏核心，不是改样式。**

### 路线 2：保持配对，把交互讲清楚

| 要做 | 影响 |
|---|---|
| 新手引导（一张图说清「点两张一样的」）| 小 |
| 选中态强化（放大 + 金边）| 小 |
| 配对成功爆炸反馈 | 中 |
| 上方加 HUD（目标 / 步数 / 进度）| 中 |

**不动关卡数据，1–2 轮能做完。**

### 路线 3：两条线并存

学习线保持配对（认知负荷低，适合学字母），
**另做一条独立的三消线**用于"玩"。

**代价最大，但两边都不牺牲。**

---

## 六、我的判断（供你否掉）

**学习场景其实不太适合真三消。**

理由：三消的认知负荷在**空间搜索**（找哪里能换），
而学字母需要的认知负荷在**字形辨认**。
两者叠加，玩家会顾着"找连击"而忽略字母。

**但你现在的问题是：它既不是三消，配对也没讲清楚，两头不靠。**

**所以我建议先走路线 2**（把配对讲清楚 + 加 HUD 填补空间），
**跑通了再决定要不要做路线 1。**
