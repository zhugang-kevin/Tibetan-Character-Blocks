# 藏文成长阶梯 · 证书体系

> 🟢 **状态：有效（已实现）** · 结论索引见 [`DECISIONS.md`](DECISIONS.md)（唯一真相源）。

> 用户为什么连续 30 天打开？因为每 10 关就有一张证书。
> 证书是学习证明，是分享素材，是收藏品，是身份升级。

积分、金币、优惠券的本质是「游戏奖励」，会被遗忘；证书的本质是「我学会了」的**能力证明**，会被保存、被分享、被收藏。

| 第六阶段 | 基字 + 上加字组词 | 51-60 | 拼带上加字的词 |
| 第七阶段 | 基字 + 下加字 | 61-70 | 认识下加字 ྱ ྲ ླ ྭ |

## 二、证书内容

```
┌─────────────────────────────────────┐
│                                     │
│         藏文成长证书                 │
│         第 1 阶段                    │
│         简单基字                     │
│         〔金质证书〕                 │
│                                     │
│    ✦ 已认识 8 个藏文字母             │
│    ✦ 已认识 4 个藏文化元素           │
│    ✦ 完成 10 个关卡                  │
│                                     │
│    证书编号：ZWFK-2026-0001          │
│    持有人：扎西                      │
│    颁发日期：2026年10月4日           │
│    学习表现：正确率 96% · 零失误      │
│                                     │
│    [藏字方块Logo]    [小程序码]       │
└─────────────────────────────────────┘
```

成就行（`✦` 那三行）**不是写死的文案**，而是运行时按真实关卡数据统计后填入的：
`utils/certificate.js` 的 `stageContent()` 会扫描该阶段全部关卡的配置，数出真实出现过的
藏文字母数、文化元素数与消除对数，再替换 `data/stages.js` 里的占位符
（`{letters}` / `{icons}` / `{elements}` / `{levels}` / `{pairs}`）。
**内容库扩充后，证书文案自动跟随，不需要改模板。**

## 三、证书的四个作用

1. **学习证明** —— 「第一阶段 · 简单基字」证书的含义是「我真的认识了这些辅音字母」。这不是积分，不是金币，是能力证明。
2. **分享素材** —— 可导出为 PNG，分享到朋友圈 / 小红书。比祝福卡更有「炫耀感」，因为这是学习成果，不是游戏奖励。
3. **收藏体系** —— 12 张证书本身即一套完整的藏文学习档案。用户会想「我还差第三阶段的证书」。
4. **身份升级** —— 每获得一张证书，文化等级提升一级。证书越多，身份越高。

## 四、颁发条件（质量门槛，不只是通关数）

| 等级 | 颁发条件 |
|---|---|
| 普通证书 | 完成 10 关 |
| 银质证书 | 完成 10 关 + 正确率 ≥ 80% |
| 金质证书 | 完成 10 关 + 正确率 ≥ 95% + 全程无失误 |

规则实现要点：

- **正确率是怎么算的**：每一关都记录 `attempts`（配对尝试次数）与 `misses`（失败次数），
  单关正确率 = `(attempts - misses) / attempts`。阶段正确率取该阶段**各关最佳正确率**的平均值。
- **只升不降**：`bestAcc` 与 `clean`（是否达成过零失误）都只增不减，所以重玩提升后会**升级**证书
  （编号不变、不新增证书），变差也不会被降级。这给「追求更高正确率」留了动力，又不会惩罚玩家。
- **无失误** 语义：本阶段任意一关都不允许出现过失败配对。若未来加入「提示」功能，
  `aggregate()` 已预留 `hints` 字段，金质门槛会同时要求「未使用提示」。
- **门槛的动机设计**：拿到普通证书后，结算页会提示「正确率提升到 80% 即可升为银质证书」，
  把「升级」变成一个明确、可达成的小目标。

## 五、证书编号

```
ZWFK-2026-0001
└┬─┘ └┬─┘ └┬─┘
 │    │    └── 流水号（4 位补零，全局递增，存于 progress.certSeq）
 │    └─────── 颁发年份
 └──────────── 前缀 ZWFK = 藏字方块拼音首字母
```

- 同一阶段无论升级多少次，**编号不变**（证书的「身份证」）。
- 只改持有人姓名也不影响编号。
- 体验版（浏览器）与小程序的编号规则完全一致。

## 六、证书与文化护照的关系

**护照是总档案，证书是护照里的签证页。**

```
我的西藏文化护照
├── 藏文成长证书 × 12 张     ← 学习线（已实现，第 1 张可颁发）
│   ├── 第一阶段：简单基字 ✅ 金质证书 ZWFK-2026-0001
│   ├── 第二阶段：简单基字组词 🔒 0/10 关
│   ├── 第三阶段：基字 + 元音 🔒 0/10 关
│   └── ...
├── 文化收藏册               ← 已实现（首次消除即收藏，x/12）
├── 地区印章                 ← 已实现（首通第 1 关得「拉萨」，规划七地市 1/7）
├── 现实足迹                 ← 二期占位
└── 个人文化图谱             ← 已实现（通关关卡 / 成长证书 / 文化卡 / 最高连击）
```

证书是藏文学习线，护照是整体文化线。两条线并行，互相支撑。

## 七、与 30 天留存的对应

| 天数 | 证书进度 | 留存动力 |
|---|---|---|
| Day 1-10 | 第一阶段进行中 | 还差几关就能拿第一张证书（首页常驻「进度 x/10 关」） |
| Day 11-20 | 第一张已拿，第二阶段进行中 | 想拿第二张证书 |
| Day 21-30 | 第二张已拿，第三阶段进行中 | 证书收集欲形成（护照 12 格「还差几张」） |
| Day 30+ | 3 张证书，进入第四阶段 | 「我已经有 3 张了，不想断」 |

首页护照入口与护照页都常驻显示 **当前阶段进度** 与 **还差几关**，是最主要的日活牵引。

## 九、内容缺口（如实说明）

阶梯规划里第一阶段的目标是「认识 **30** 个辅音字母」，但**当前内容库只有 8 个藏文字母
（ཀ ཁ ག ང ཅ ཆ ཇ ཉ）+ 4 个文化元素 = 12 个元素**，10 关全部由它们组成。

因此本次实现采取的做法是：

- **证书文案按真实数据生成**：当前会显示「已认识 8 个藏文字母」，而不是写死「30 个」。
  这样证书不会说假话，用户拿到的每一句都是真的。
- 阶梯里的 `plan: '认识 30 个辅音字母'` 字段保留了完整规划，作为内容扩充的目标依据。
- 内容扩充到 30 个字母后，**证书文案会自动变成「已认识 30 个藏文字母」，无需改代码**。

### 二期扩展清单（内容）

1. 元素库补足到 30 个辅音字母（`data/elements.js`），并为每个字母补一张文化卡（`data/cards.js`）。
2. 重排第 1-10 关的元素分布，让 30 个字母在 10 关内循序渐进地出现。
3. 新增第二阶段的 20 个词（10-20 关）、第三阶段的元音符号等（`data/levels.js` + `data/stages.js` 置 `open: true`）。
4. 第二阶段及以后只需把 `stages.js` 里对应阶段的 `open` 改为 `true` 并补上 `certLines`，
   证书体系本身不需要改动。

## 十、验证方式

```bash
node scripts/validate.js       # 第 14 类：成长阶梯与证书体系（阶梯数据 / 门槛 / 编号 / 页面 / 镜像）
node scripts/test-h5.js        # 第 14-19 节：阶梯数据 / 正确率统计 / 颁发与升级 / 护照 / 证书页 / 持久化
```

端到端测试覆盖的关键断言：

- 正确率不足时**只发普通证书**；零失误通关后**升级为金质**，且**编号不变、不新增证书**。
- 已有更高等级证书时，之后再出现失误**不会被降级**。
- 护照恰好渲染 **12 个证书位**（1 个高亮 + 11 个灰色锁定）。
- 证书页在未获得时展示锁定说明与三级门槛规则。
- 证书编号形如 `ZWFK-YYYY-NNNN`，首张为 `0001`。
