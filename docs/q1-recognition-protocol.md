# Q1 识认率采集协议（n≥30）

> 目的：回答"玩家是否真的认字"，而不是"配对是否成功"。
> 工具已在代码里：`pages/recognition`（30 题、四选一、无颜色 / 无发音 / 无提示）。
> 评分口径：`utils/recognition.js`（30 题、≥80% 即 24/30 达标、n≥30 才报达标率）。

## 0. 工具在哪

| 场景 | 工具 | 说明 |
|---|---|---|
| 小程序发布后 / DevTools | `pages/recognition` | 同源题库；`?seed=N` 可复现 |
| **发布前外部用户** | `preview/q1.html` + `preview/q1-data.js` | 纯本地、无服务器、无音频、无颜色；可导出 JSON/CSV |
| 统计 | `scripts/q1-report.js` | 读 CSV 出 n、达标率、95% Wilson CI、前后测增益 |

网页版题库由 `node scripts/gen-q1-data.js` 从 `data/cards.js` + `data/learning.js` 生成（30 条，转写唯一）。
改了题库就重跑一次，别手改 `q1-data.js`。

网页版已实测：30/30 → 达标；故意错 1 题 → 29/30 仍达标，错题定位正确；页面无 `<audio>`、无提示入口。

## 1. 两种问题，别混

| 问题 | 需要的设计 | 能回答什么 |
|---|---|---|
| 现在能认多少？ | **单次 Q1** | 识认率（横截面） |
| 学完有没有提升？ | **前测/后测（同一批人）** | 学习增益（因果更强） |

只做单次 Q1，**不能**说"150 课教会了认字"；只能说"当前识认率是 X%"。
要做"教会"，必须做前测/后测。

## 2. 样本

- **n ≥ 30**（平台口径）；建议招 35–50 人，防流失。
- 人群：至少覆盖"零基础"和"学过一点"两档；记录年龄段（不记姓名/手机号）。
- 排除：藏文母语者、系统学过藏文超过 1 个月者（另列，不混入）。
- 知情同意：说明"匿名、可随时退出、结果只用于产品改进"；**不收集**姓名/手机号/微信昵称。

## 3. 流程（前测/后测版）

1. 给每位参与者一个**匿名编号**（如 A01、A02），只写在记录表上。
2. **前测**：打开 `pages/recognition` → 读完说明 → 30 题 → 记录 `correct / items`（页面显示）。
   - 不要提示、不要翻译、不要让他查资料；一次做完。
3. **学习**：完成 L1（10 课）或 L1–L3（30 课）；记录完成课数。
4. **后测**：同一编号，再打开 `pages/recognition`（**新的 seed**）→ 30 题 → 记录。
5. 把两次数值填入 `docs/q1-sample-sheet.csv`（列：code, group, pre_correct, pre_items, post_correct, post_items, lessons_done, date, device, notes）。
   - **网页版更快**：结果页点「导出记录表行」→ 直接得到一行 CSV（前测填 `pre_*`、后测/单次填 `post_*`），粘贴到表里即可；
     「导出 JSON」留明细（逐题对错）。已实测：前测行 `A01,zero,30,30,,,10,...`。
6. 跑 `node scripts/q1-report.js docs/q1-sample-sheet.csv`，得到 n、前后均值、增益、达标率与 95% CI。

> 单次版：只填 `post_*`（或 `pre_*` 留空），报告只出横截面，不出增益。

## 4. 记录表字段

- `code`：匿名编号（A01…），**不要**写姓名。
- `group`：zero / some / native（母语者单列，不混）。
- `pre_correct` / `pre_items`：前测正确数 / 题数（通常 30）。
- `post_correct` / `post_items`：后测。
- `lessons_done`：两次测验之间完成的课数（0 表示只做单次）。
- `date` / `device` / `notes`：日期、机型、异常（如中途退出）。

## 5. 指标与口径

- 个人达标：`items ≥ 30` 且 `correct/items ≥ 0.8`（24/30）。
- 群体：
  - `n`：有效人数（前后测都完整）。
  - `meanPre` / `meanPost`：平均正确率。
  - `gain`：`meanPost − meanPre`（配对人群）。
  - `passRate`：后测达标比例；报 **95% Wilson CI**。
- **n < 30 不报达标率**，只报描述统计（均值/范围）。
- 不用"配对成功率"替代；不用"提示题"；不删低分样本（除非有记录的中断）。

## 6. 结果怎么读

- 若 `gain` 的 95% CI 跨 0：**不能**说"显著提升"。
- 若 `passRate` 的 CI 很宽（样本小）：只说"初步"，不说"达标"。
- 若前测已经很高（天花板）：换更难的题库（L11+ 词汇/句子），否则测不出教学效果。

## 7. 与线上遥测的关系

- 线上 `recognition_end` 只带 `items/correct/rate/pass/seed`，**匿名、无 uid**，可做总体分布；
  但**不能配对**前后测。要做增益，必须用第 3 节的匿名编号表。
- 遥测适合"有没有异常/大致水平"，不适合"因果"。

## 8. 发布前的最低要求

1. 至少 30 人完成**单次** Q1（横截面）。
2. 若对外说"课程有效"，至少 20 人完成**前后测**，并报告增益 + CI。
3. 所有原始记录表留存（匿名），可复核。
