## 二、上线路径（两阶段）

### 2.0 先回答一个必问的问题：**小程序不是通过公众号发布的**

**小程序有自己独立的账号与后台**（微信公众平台 mp.weixin.qq.com，注册时选「小程序」而不是「公众号」）。
发布动作全部在小程序自己的后台完成，**与公众号没有从属关系**。

| 常见误解 | 事实 |
|---|---|
| 「小程序挂在公众号下面，从公众号发布」 | ❌ 两者是**平行**的账号类型，各有独立账号、独立后台、独立审核 |
| 那公众号有什么用？ | ✅ **引流入口**：公众号可**关联**小程序，把小程序放进自定义菜单、文章内链、模板消息——但**发布/审核/版本管理都不在公众号侧** |
| 没有公众号能上线吗？ | ✅ **能**。公众号是**可选的推广渠道**，不是发布前提 |

> 一句话：**发布看小程序后台，公众号只负责把人带进来。**

### 2.1 提审 → 发布 的具体动作（开发者工具 + 小程序后台）

| 阶段 | 在哪做 | 动作 |
|---|---|---|
| ① 上传代码 | 微信**开发者工具**（右上「上传」） | 填版本号（如 `1.0.0`）与备注 → 代码进入后台「开发版本」 |
| ② （可选）体验版 | 小程序后台 | 选一个开发版本设为体验版，加白名单成员真机试玩 |
| ③ 提交审核 | 小程序后台 → 版本管理 → 开发版本 | 填：功能页面（≤5 组）、测试账号（如需登录）、隐私指引已配置 |
| ④ 等待审核 | — | 2026 年常规 2–12 小时；新号首发/复杂功能更久 |
| ⑤ 发布 | 小程序后台 → 版本管理 → 审核版本 | **审核通过不会自动上线**，必须管理员**手动点「发布」** |
| ⑥ 发布模式 | 同上 | **首次必须「全量发布」**；之后可灰度（分阶段发布） |

> AppID `wx52ce3d2b35ade6ef`）。→ 可直接走 **§2.2「复用公众号资质快速注册并认证小程序」**，
> **省掉重新提交主体材料、对公打款、以及 300 元认证费**。

### 2.2 复用公众号资质快速注册小程序（本项目推荐路径）

**依据**：腾讯客服《公众号/服务号快速注册并认证小程序》——
境内**已认证**的企业/媒体/其他组织类型公众号（**含个体工商户**）可复用资质注册；
**无需重新提交主体材料、无需对公打款、无需支付 300 元认证费用**；
选择复用认证资质时，**小程序注册完成即处于「已认证」状态**。

| 项目 | 说明 |
|---|---|
| 入口 | 登录**公众号**后台 → 广告与服务 → 小程序管理 → 关联小程序 → 添加 → **快速注册并认证小程序** |
| 步骤 | 同意协议 → 管理员扫码验证 → **勾选复用认证资质** → 填小程序账号信息 → 邮件激活 → 绑定管理员 |
| ⚠️ 名额限制 | **个体工商户：一个月只能复用 1 次**（企业为 5 次）。**只有一次机会，名称与邮箱必须一次想清楚** |
| ⚠️ 占位规则 | 若已存在「**待完成注册**」的小程序，**不能**再发起复用注册 → 别中途搁置 |
| ⚠️ 邮箱要求 | 必须是一个**从未绑定过任何个人微信 / 公众号 / 服务号 / 小程序 / 开放平台**的邮箱 |
| 自动关联 | 复用创建的小程序**默认与该公众号关联** → 公众号自定义菜单、文章可直接挂小程序入口（免费引流） |
| 认证有效期 | 小程序**初始认证有效期与公众号一致**；之后的**年审要在小程序后台独立申请** |
| AppID | 小程序会拿到**它自己的 AppID**（≠ 公众号的 `wx52ce3d2b35ade6ef`）→ 填进本项目 `project.config.json` |

**名称规则**：同一主体下，**小程序可以与自己的公众号同名**；跨主体重名不可用。
→ 「雪域智语」可用；若要独立品牌（如「藏趣方块」）也可，两者都在同一主体名下。

### 2.2b 服务号里**已经有别的小程序**，会不会冲突？（2026-10-19 核实）

**结论：一般不会冲突。** 官方规则（腾讯客服《公众号/服务号快速注册并认证小程序》）：

| 规则 | 含义 |
|---|---|
| 复用资质创建的小程序**默认与该服务号关联** | 新小程序会自动挂到服务号下 |
| 默认关联**不占**「一个月新增关联 13 个小程序」的名额 | 所以"已经有几个"不影响这次 |
| 一个服务号**可关联多个**小程序 | 同时存在 2 个、3 个是常态，不是冲突 |

**但有三件事会真的挡住你，逐一确认**：

| # | 情况 | 影响 | 怎么查 |
|---|---|---|---|
| 1 | **个体户一个月只能复用 1 次**（企业 5 次） | ⚠️ **这是唯一的硬名额**。若那个"服务产品"是**本月用复用注册的** → 这个月就不能再复用，需等下月或走普通注册（要重交材料 + 300 元） | 服务号后台 → 小程序管理，看该小程序的来源/创建时间 |
| 2 | 存在「**待完成注册**」的小程序 | ✗ 直接**不允许发起**复用注册 | 同上，看有没有"待完成注册"状态 |
| 3 | 那个"服务产品"只是**关联**进来的（第三方商城/SaaS） | ✅ **不占名额**，完全无影响 | 关联 ≠ 复用注册，不消耗个体户那 1 次 |

**两个容易误会的点**：
- **不是"通过服务号上传"** —— 是"用服务号的**资质**去注册一个小程序"。注册完成后，
  **上传代码 / 提审 / 发布都在小程序自己的后台**，和服务号无关（服务号只负责关联与引流）。
- 复用创建的小程序**不会自动出现在服务号资料页**，也**不下发模板消息** →
  想放入口，要自己在服务号菜单/资料页里手动配置。

**仍需以系统提示为准**：不同渠道的资料对"复用认证资质后是否仍需单独认证"说法不一致
（官方客服页写明"复用认证资质 → 注册完成即已认证、不再收 300 元"）。
**照系统实际显示走**，若出现收费提示再当场判断。

### 2.3 主体资质与经营范围的差距（2026-10-17 核对营业执照）

> 🔴 **先给结论，避免误伤**：**改经营范围不是上线的必选项。**
> 决定一切的是**服务类目**属于哪一档 —— 见下表。走**「工具类」不需要改经营范围**。

**好消息**：主体类型为**个体工商户**，且已有**已认证**的公众号（雪域智语）
→ §2.2 的复用注册路径可用 ✓

平台把服务类目分三档（2026 口径）：

| 档位 | 资质要求 | 本项目相关类目 |
|---|---|---|
| **普通准入类** | **只需主体营业执照**，不需额外资质 | ✅ **工具类**（官方口径明确「适合展示型、工具类、普通咨询类」） |
| **资质核验类** | 需对应行业许可证（食品经营、卫生许可、**办学许可**…） | ⚠️ 教育培训 → 需《办学许可证》 |
| **专项审批类** | 国家级专项资质，审核 30 天以上 | ⚠️ 文娱内容 → 可能涉《网络文化经营许可证》 |

**逐项核对现有经营范围**（纯百货零售口径）：

| 类目可能需要的资质依据 | 现有经营范围 |
|---|---|
| 教育 / 培训 / 咨询 | ❌ 没有 |
| 软件 / 信息技术 / 技术服务 | ❌ 没有 |
| 文化 / 艺术 / 文艺创作 | ❌ 没有 |
| 零售 / 互联网销售 / 文具 / 玩具 / 工艺美术品 | ✅ 有 |

**结论（三条，按重要性排序）**：

1. ✅ **走「工具类」→ 不需要改经营范围、也不需要额外资质** —— 最省事的路线。
   代价：必须把产品做成**非游戏观感**，否则会被判「类目与内容不符」
   → 执行 §三 的**去游戏化清单**（该清单本项目早已列好）。
2. ⚠️ **改经营范围 ≠ 能走教育类目**：教育培训属「资质核验类」，要的是**《办学许可证》**，
   这不是改经营范围能解决的 → **这条路不建议走**。
3. 🕐 **改经营范围什么时候才需要**：等**收服务费 / 开票**（变现阶段）再办即可，
   现在不阻塞上线。届时从登记机关**标准条目库**增选：
   `软件开发` · `信息技术咨询服务` · `技术服务、技术开发、技术咨询…` ·
   `教育咨询服务（不含涉许可审批的教育培训活动）` · `文艺创作 / 组织文化艺术交流活动`。
   → 目标是「**有依据、不触发前置审批**」，**别加「培训」**。
   具体条目以登记机关系统为准。

**最终以小程序后台为准**：登录小程序后台 →「设置 → 基本设置 → 服务类目」→
看系统**当场提示**的资质要求再定路线（见 §三）。

## 三、类目选择的权衡（**最大风险点**）

我们的产品是「消除玩法 + 藏文启蒙」。**「类目与内容不符」是 2026 年最高频的驳回理由**——后台选「工具/教育」，但内容有明显关卡、积分、连击，审核会直接判定属于游戏内容却没选游戏类目。

| 路线 | 可行性 |
|---|---|
| **教育 - 素质教育 / 文化** | ✅ **唯一可行**。教育属性真实（每个元素都有知识卡 + 藏语发音 + 成长阶梯 + 证书），不是包装。**必须配合「去游戏化」文案改造** |
| 游戏 - 休闲益智 | ❌ 当前设定下不可选。个体户做轻休闲小游戏**必须广告变现**才免版号，而我们已定「无广告」→ 无变现通路 |

**「去游戏化」改造清单**（阶段 0 必做，实施细节见 [`business-model-v2.md`](business-model-v2.md) §3）：

| 现在 | 改成 |
|---|---|
| 第 N 关 | 学习单元 N / 第 N 课 |
| 积分 | 学习得分 |
| 连击 ×N | 连续正确 ×N |
| 金色方块（双倍积分） | 重点字（双倍练习） |
| Slogan「玩方块，认藏文」 | 「认藏文，从方块开始」（备选） |
| 引导页「如何消除」 | 「如何使用」 |

**无论走哪条路，软著都要先办。** 另外：**提审版本里不要预埋任何支付代码**。

> ⚠️ **提审前必须核实的一件事：教育类目要不要行业资质。**
> 平台对**特殊行业**类目要求前置资质，教育是其中之一——公开资料里最常见的要求是
> 《办学许可证》或《民办非企业单位登记证书》，且**营业执照经营范围**需含教育相关字样
> （只写「软件开发 / 信息技术服务」会被判资质不符）。
> 但「教育 - 素质教育 / 文化」与「教育培训」的资质要求**未必相同**，且平台规则会调整。
> **做法**：登录小程序后台 →「设置 → 基本设置 → 服务类目」→ 找到目标类目，
> 看系统当场提示的「资质要求」——**以那里的提示为准**，不要凭二手文章判断。
> 若确实需要办学许可，则需重新权衡：改选更贴切且免资质的类目，或调整产品定位。

## 四、微信支付商户号开通流程（个体工商户）

1. 主体小程序认证通过后，进「微信公众平台 → 微信支付 → 开通」
2. 准备材料：营业执照、经营者身份证、结算银行卡（个体户可用经营者个人卡）
3. 填写经营类目（与营业执照经营范围一致）、客服电话
4. 审核通过后获得商户号（mchId），费率一般 0.6%，T+1 结算

## 八、藏文发音的 TTS 预生成（D45，2026-10-07）

> 目标：把 34 条元素发音 + 2 条情绪语音（`audio/voice/*.mp3`）生出来，
> 让「配对成功后的发音播报」在真机上有声音。**运行时零请求，不建任何后端。**

### 8.1 为什么是「预生成」而不是「运行时调用」

D36⑥ 否决的是**运行时云函数调 TTS**（每播一个音都要联网 + 云函数 + 域名备案，撞 D3/D13）。
而发音内容是**完全固定的 36 条文本**，一次性离线生成后就是普通静态资产——
与「真人录音」在工程上是同一种东西。因此：

| 方案 | 结论 |
|---|---|
| 运行时云函数 TTS | ❌ 维持否决（D36⑥） |
| **离线预生成（本方案）** | ✅ 推荐：一次生成、永久缓存、零运行时成本 |
| 真人录音 | ✅ 质量天花板，作为后续 Gate 2 素材 |

### 8.2 推荐服务：天翼 AI 开放平台「卫藏实时超自然语音合成」（已接入，WS 协议）

- 平台：`teleai.com.cn`（民族语言大模型专区），中国电信运营，国内节点；
- 方言：卫藏（拉萨）——与本项目「标准拉萨音单读」的口径一致；
- 接口：`wss://openapi.teleagi.cn:443/aipaas/voice/v1/weizStreamingSuperTts/streaming`（WebSocket 流式，
  输出 PCM 16bit 单声道，base64 分片 + `is_end` 收尾；单次 ≤500 字符；音色 `zhuoma`（卫藏方言）；
  ⚠️ 本产品 `Device-Uuid` 必填——见下方 8.5 排障）；
- 鉴权：`Authorization = teleai-cloud-auth-v1/{AppID}/{region}/{ts}/{exp}/{signedHeaders}/{sig}`，
  `SigningKey = HMAC-SHA256-HEX(AppKey, prefix)`、`Signature = HMAC-SHA256-HEX(SigningKey, CanonicalRequest)`；
  签名算法已按官方《签名认证方式》文档在 `scripts/gen_voice.py` 内实现（零第三方依赖）；
- **路径已实测**（2026-10-07）：用占位 Key 探测真实服务器返回 `HTTP 401 {"code":"10010004","message":"签名认证失败"}`
  —— 证明网络 / TLS / WS 握手 / 签名头 / 接口路径全部正确，只差真实 AppKey；
- 步骤：
  1. 控制台「应用及 API Key」打开该应用（如 APP-00006447），复制 **AppID 与 AppKey**；
  2. 填进 `scripts/tts-config.json`（该文件已被 `.gitignore` 屏蔽，密钥不会入库）；
  3. 验鉴权：`python scripts/gen_voice.py --probe`（期望输出「✓ 鉴权通过（101 success）」）；
  4. 先试一条：`python scripts/gen_voice.py --only letter_01`——**试听后再全量**；
  5. 全量：`python scripts/gen_voice.py`（幂等，已存在的自动跳过；失败单条不影响整批）。
