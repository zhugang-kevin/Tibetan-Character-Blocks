## 一、现状与结论

- 当前 MVP **不含任何支付功能**（规格红线：不做商城/支付），进度存储全在本地。
- 主体选择结论：**注册个体工商户**。理由：主体类型不可变更，签合同、开票、微信支付商户号都需要组织主体，个体工商户成本最低（**年认证费 300 元**，见下）且能力够用。
  - ⚠️ 本文档早期版本写的「30 元/年」是**错误**，已修正为 **300 元/年**（微信认证统一价）。
- 变现路线（2026-10 校准）：**无广告**。走「商家核销服务费 + 公益导流服务费」，**小程序内不放支付**。详见 v2 文档。
  - 早期版本建议的「纯广告变现」路线**已排除**，保留在此仅为记录。

## 二、上线路径（两阶段）

### 阶段一：无支付上线（现在就能做）

| 步骤 | 事项 | 说明 |
|---|---|---|
| 1 | 注册个体工商户 | 当地市场监管局或线上办理；经营范围写「软件开发」或「信息技术服务」 |
| 2 | 注册微信小程序 | 用个体户执照注册（个人主体注册后不可变更，勿用个人身份先上线） |
| 3 | 替换 AppID | 本项目 `project.config.json` 中 `appid: "touristappid"` → 你的正式 AppID |
| 4 | 微信认证 | **300 元/年**，解锁组织主体能力 |
| 5 | **ICP 备案** | 必办，免费，1-20 个工作日；境内小程序未备案不得上线 |
| 6 | 申请软件著作权 | 周期 1-2 个月，费用约 800-1500 元；教育/游戏化内容上线的基础门槛 |
| 7 | 提交审核发布 | 类目要求见下（**类目判定是最大风险**） |

### 阶段二：开通变现（有用户后）

1. **微信支付商户号**：个体户可开通，费率 0.6%~1%，享小微 9 折（**优惠有效期已续期至 2027-09-30**）。用途见 v2 文档——**用于收取服务费与开票，不接入小程序内收款**。
2. ~~**广告（流量主）**~~：**已排除**（2026-10 校准为无广告模式）。
3. **虚拟支付/内购**：⚠️ **原结论「个体户不可行」已作废（2026-10 更正）**。原判断混淆了**小游戏**与**小程序**：小游戏虚拟支付确需版号（关闭），但**小程序**虚拟支付官方开通条件仅「已认证 + 企业/事业单位/个体工商户 + 信息完备」，**无需版号**；个人主体亦可开（限「工具」类目、月限额 10 万）。iOS 端 2025-11 苹果与腾讯和解后已打通（走苹果 IAP，苹果抽 15%）。参见 [`monetization-v3.md`](monetization-v3.md)。

## 三、类目选择的权衡（**最大风险点**）

我们的产品是「消除玩法 + 藏文启蒙」。**「类目与内容不符」是 2026 年最高频的驳回理由**——后台选「工具/教育」，但内容有明显关卡、积分、连击，审核会直接判定属于游戏内容却没选游戏类目。

| 路线 | 可行性 |
|---|---|
| **教育 - 素质教育 / 文化** | ✅ **唯一可行**。教育属性真实（每个元素都有知识卡 + 藏语发音 + 成长阶梯 + 证书），不是包装。**必须配合「去游戏化」文案改造** |
| 游戏 - 休闲益智 | ❌ 当前设定下不可选。个体户做轻休闲小游戏**必须广告变现**才免版号，而我们已定「无广告」→ 无变现通路 |

**「去游戏化」改造清单**（阶段 0 必做，实施细节见 [`business-model-v2.md`](business-model-v2.md) §3）：

| 现在 | 改成 |
|---|---|
| 第 N 关 | 学习单元 N / 第 N 课 |
| 积分 | 学习得分 |
| 连击 ×N | 连续正确 ×N |
| 金色方块（双倍积分） | 重点字（双倍练习） |
| Slogan「玩方块，认藏文」 | 「认藏文，从方块开始」（备选） |
| 引导页「如何消除」 | 「如何使用」 |

**无论走哪条路，软著都要先办。** 另外：**提审版本里不要预埋任何支付代码**。

## 四、微信支付商户号开通流程（个体工商户）

1. 主体小程序认证通过后，进「微信公众平台 → 微信支付 → 开通」
2. 准备材料：营业执照、经营者身份证、结算银行卡（个体户可用经营者个人卡）
3. 填写经营类目（与营业执照经营范围一致）、客服电话
4. 审核通过后获得商户号（mchId），费率一般 0.6%，T+1 结算
5. 在商户平台设置 API 密钥（APIv3 密钥）并绑定 AppID
6. **代码接入**：由我实现 `wx.requestPayment` 下单签名流程（需要服务端参与，纯前端无法安全签名——届时需搭配云开发云函数托管签名逻辑，避免泄露商户密钥）

## 六、避坑提示

1. 🚨 **绝对禁区：不要代收交易款再转给商家。**「用户付款 → 资金进你的商户号 → 你拆分给商家」构成**无证二次清算（二清）**，违反央行银发〔2016〕217 号文，会被关停通道、冻结资金、行政处罚。合规做法是商家用自己的收款渠道收款，你只收**导流服务费**（详见 v2 §2.1）。
2. **主体类型不可变更**——不要图省事用个人身份先上线。
3. **类目判定是第一道闸门**，不是最后一步。内容有游戏元素却报教育类目，会被直接驳回。
4. **不要在审核版本里预埋支付代码**：没有商户号时提交含 `wx.requestPayment` 的版本会被驳回。
5. **ICP 备案必办**，且服务器须在中国大陆境内，未备案不得上线。
6. **不要在公益叙事里用「募捐 / 捐款 / 慈善募捐」**——那是《慈善法》下的公开募捐，需专门资质。用「公益合作 / 助残导流」等商业表述。
7. **政策以当期规则为准**——本指南写于 2026-10-04，提交前到微信公众平台复核一次。

### C-2. 上线前必须在公众平台配置（否则功能被拒）

1. **《小程序用户隐私保护指引》**：本项目用到 `wx.saveImageToPhotosAlbum`（保存证书 / 祝福卡 / 祝福签到相册），
   属平台「受保护接口」。未配置隐私指引、或未在调用前取得用户同意，接口会直接失败。
   代码侧已完成前置（`utils/privacy.js` 统一走 `wx.getPrivacySetting` → `wx.requirePrivacyAuthorize`），
   **后台配置必须由你完成**：公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引 → 勾选「相册（**仅写入**）」并提交审核。
   - ⚠️ **驳回高发点**：「相册（仅写入）」的用途描述**只能写「保存 XX 图片」这一类**，
     写「上传图片 / 编辑个人信息 / 发布 / 扫码」会被判为与接口不符而驳回（官方社区明确列为最常见驳回原因）。
     ✅ 建议照抄：「保存藏文成长证书、祝福卡与祝福签到用户相册（仅写入，不读取、不上传）」。
   - ⚠️ 配置后需 **2–4 小时生效**；小程序未发布上线前无法真实验证隐私功能（`__usePrivacyCheck__` 不要手填）。

3. **字体域名白名单**：若配置了 `TIBETAN_FONT_URL`，该域名需加入「downloadFile 合法域名」。
