# 藏字方块 · 上线与支付开通指南

> 更新：2026-10-04 · 配合《藏字方块》MVP（tibetan-match）使用

## 一、现状与结论

- 当前 MVP **不含任何支付功能**（规格红线：不做商城/支付），进度存储全在本地。
- 主体选择结论：**注册个体工商户**。理由与你的分析一致——主体类型不可变更、虚拟支付/内购/签合同/开票都需要组织主体，个体工商户成本最低（年认证费 30 元）解锁能力最全。
- MVP 阶段先以**纯广告变现**目标上线（无需版号），支付能力等主体下来后再接。

## 二、上线路径（两阶段）

### 阶段一：无支付上线（现在就能做）

| 步骤 | 事项 | 说明 |
|---|---|---|
| 1 | 注册个体工商户 | 当地市场监管局或线上办理；经营范围写「软件开发」或「信息技术服务」 |
| 2 | 注册微信小程序 | 用个体户执照注册（个人主体注册后不可变更，勿用个人身份先上线） |
| 3 | 替换 AppID | 本项目 `project.config.json` 中 `appid: "touristappid"` → 你的正式 AppID |
| 4 | 微信认证 | 30 元/年，解锁组织主体能力 |
| 5 | 申请软件著作权 | 周期 1-2 个月，费用约 800-1500 元；游戏/教育类目上线的基础门槛 |
| 6 | 提交审核发布 | 需自审自查报告（类目要求见下） |

### 阶段二：开通变现（有用户后）

1. **广告（流量主）**：小程序累计独立访客（UV）≥ 1000 即可开通。可在结算页、首页底部挂 Banner，消除成功后挂激励视频（复活/提示道具场景天然契合）。这是无版号阶段唯一的正规变现方式。
2. **微信支付（普通支付）**：个体户可开通商户号，卖实体/服务类商品没问题。
3. **虚拟支付/内购**：涉及则需版号，且 iOS 端受苹果 IAP 政策约束（微信虚拟支付能力仅对部分类目开放，政策变动频繁，开通前务必查微信公众平台最新规则）。

## 三、类目选择的权衡（重要决策）

我们的产品是「消除玩法 + 藏文启蒙」，有两条类目路线：

| 路线 | 优势 | 风险 |
|---|---|---|
| 游戏 - 休闲益智 | 玩法定位名正言顺 | 需软著；小游戏类目对版号的要求以平台最新政策为准 |
| 教育 - 素质教育 / 文化 | 教育属性强，审核叙事顺（每个元素都有教学卡片） | 若审核认定核心是"玩法"可能被要求改挂游戏类目 |

**建议**：申报时强调"藏文识字启蒙工具"的教育叙事（配对是记忆手段、文化卡是内容主体），优先尝试教育/文化类目；被驳回再转游戏类目。无论哪条路，软著都要先办。

## 四、微信支付商户号开通流程（个体工商户）

1. 主体小程序认证通过后，进「微信公众平台 → 微信支付 → 开通」
2. 准备材料：营业执照、经营者身份证、结算银行卡（个体户可用经营者个人卡）
3. 填写经营类目（与营业执照经营范围一致）、客服电话
4. 审核通过后获得商户号（mchId），费率一般 0.6%，T+1 结算
5. 在商户平台设置 API 密钥（APIv3 密钥）并绑定 AppID
6. **代码接入**：由我实现 `wx.requestPayment` 下单签名流程（需要服务端参与，纯前端无法安全签名——届时需搭配云开发云函数托管签名逻辑，避免泄露商户密钥）

## 六、避坑提示

1. **主体类型不可变更**——不要图省事用个人身份先上线。
2. **iOS 虚拟支付**：苹果生态内虚拟商品支付受 Apple 政策约束，微信对 iOS 小程序虚拟支付长期从严；若未来做内购，优先保证安卓侧收入模型成立。
3. **不要在审核版本里预埋支付代码**：没有商户号时提交含 `wx.requestPayment` 的版本会被驳回；支付作为独立迭代上线。
4. **签名永远放服务端**（云函数），前端只拿 `timeStamp/nonceStr/package/signType/paySign` 五件套调起收银台。
5. 政策类目要求以微信公众平台当期规则为准，本指南写于 2026-10，提交前请复核。
