## 三、🔴 过程中会撞到的技术障碍（已全部挖出并给出解法）

### 障碍 1 · `.m4a` 会**静默进包但永远不播**（最严重，必须处理）

**证据链**：

| 检查项 | 结论 |
| --- | --- |
| 门禁 §47.6 残留检查 | `vfiles.filter(f => /\.wav$/i.test(f))` —— **只查 `.wav`，不查 `.m4a`** |
| 门禁 §47.6 体积统计 | `vfiles.filter(f => /\.mp3$/i.test(f))` —— **只统计 `.mp3`** |
| `project.config.json` 忽略规则 | 只排除 `folder: preview/docs/...` 与 `suffix: .py/.md` —— **`.m4a` 不在排除列表** |
| `utils/audio.js` `pronounce()` | 尝试顺序固定：`.mp3` → 失败 → `.wav` → **没有 `.m4a` 分支** |

**后果链**：把`六字真言.m4a` 直接丢进 `audio/voice/` →
① 微信打包器把它当 `audio/` 资产**打进主包（+80KB）** →
② 门禁 §47.6 **看不见它**（既不报残留也不计入 420KB 总量）→ **假绿** →
③ 运行时 `pronounce('六字真言')` 找 `.mp3` 找不到、找 `.wav` 找不到 → **静默无声**
→ **玩家点了喇叭没反应，而你以为已经修好了。**

这正是项目 D56 记录过的同一类病：「文件存在 ≠ 文件有声 / 被播到」。

**✅ 解法（我执行，你不用管）**
1. 统一转 `.mp3`（16kHz 单声道）后再入库 —— 项目既有口径
2. **加一道门禁**：`audio/voice/` 出现 `.m4a`/`.aac`/`.wma` 等非 `.mp3`/`.wav` 音频即报错
3. 在 `utils/audio.js` 的 `__triedWav` 之后再加 `.m4a` 兜底分支（防御性，双保险）

### 障碍 3 · 峰值贴顶，归一必须**降增益**而非升增益

五段峰值全部在 **−0.0 ~ −0.2 dBFS**（几乎满量程），而项目口径要求峰值 ≤ −1.5 dBFS。
所以 `normalize_voice.py` 会**降低** 1.3–1.5 dB：

| 文件 | 采用增益 | 归一后 RMS | 结果 |
| --- | --- | --- | --- |
| `1.m4a` | −1.5 dB | −24.6 dBFS | 比 −20 低 4.6 dB |
| `2.m4a` | −1.3 dB | −25.5 dBFS | 低 5.5 dB |
| `3.m4a` | −1.4 dB | −23.9 dBFS | 低 3.9 dB |
| `六字真言` | **+2.9 dB** | −21.5 dBFS | 低 1.5 dB（唯一可升的） |
| `雪山.m4a` | −1.4 dB | −21.7 dBFS | 低 1.7 dB |

**这不是缺陷，是你的录音本来就录得很满（动态压得小）**。
后果：四条会比项目标准音量**轻 4–5.5 dB**。
`utils/audio.js` 有 BGM ducking（语音期间 BGM 压到 0.10），能部分补偿。
**但我要如实说：这四条入库后会比现有 TTS 语音偏轻。**

**✅ 三个选项（你选，或让我选）**

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| **A（我推荐）** | 逐段**动态压缩**后再归一（用 ffmpeg `acompressor`） | 需重跑一次处理；压缩会改变动态起伏，但换来响度统一 |
| B | 保持静态增益，接受轻 4–5.5 dB | 零成本；玩家可能觉得"藏语有点轻" |
| C | 重录，峰值留 −6 dB 余量（离麦远一点/轻一点念） | 需你重录5 段 |

**注意**：D59 记录过项目曾明确选择**静态增益而非动态压缩**（理由：压缩会改变呼吸与句尾收弱）。
所以选 A 等于**推翻D59 的一个既有决定**，需要你明确拍板，我不会自己改。

### 障碍 5 · `gen_voice.py` 会不会覆盖你的录音

`run()` 里 `if os.path.exists(out) and not force: skip` —— 默认**幂等跳过**，不会覆盖。
但若有人跑 `--force`（`normalize_voice.py` 注释里就提到过 `--force` 的用法），会**覆盖真人录音**。

**✅ 解法**：把真人录音登记进 `KNOWN_BLOCKED` 同级的「人工音源保护名单」，
并在 `gen_voice.py` 加一道硬拦截 + 门禁 §47 一条检查。**这条必须做，否则某天一次 force 就白录了。**

### 障碍 8 · `mantra_4x` 门禁 §59.22 的时长比判据

门禁要求 `dur(mantra_4x) / dur(mantra) ≥ 3.5`。
若单遍 = 1.8s，4 遍拼接 ≈ 1.8×4 + 0.35×3 = **8.25s**，比值 = **4.58** ✅ 通过。
但如果裁剪后单遍只剩 1.0s，比值可能掉到 4.0 左右——**仍通过**，但我会在跑之前实测确认。
