# 广告变现：能做，但不是「没有限制」（2026-10-21）

> 你的判断是「如果广告是最好的赚钱门路，而且没有任何限制」。
> **前半句要打折，后半句不成立。** 这份文件把限制逐条列出来，再给能放的位置。

---

## 0. 一句话

**广告不是"最好的门路"，是"最不需要用户掏钱"的那条。**
它的天花板是**流量**，不是转化率 —— 而我们现在流量是 0。
**限制也很多，只是限制集中在"开通门槛"和"展示纪律"，不是"资质"。**

顺序建议不变：**先把虚拟支付接通（那是能力，开通就永久可用），广告等有 UV 再接。**

| # | 限制 | 出处 / 性质 |

| 1 | **累计独立访客 UV ≥ 1000 且无违规记录**才能开通流量主 | 微信开放社区官方公告 —— **原文** |
| 2 | 小程序需**已认证**（未认证的账号流量主可能是关闭状态） | 社区文章 —— **二手，待你在后台确认** |

| 4 | 「每个用户每天可观看激励式视频广告的**次数有限**」 | 《激励视频广告》官方文档 —— **原文** |

| 7 | 插屏**不能一进小程序就弹**、**不能用在首页** | 社区文章 —— **二手，但方向可信**（我们已按更保守的 30 秒 + 5 分钟间隔自我约束） |

**结论**：广告不是"没限制"，是**限制在流量门槛和使用纪律上**。资质方面确实没有额外许可要求（比虚拟支付的版号风险低），这点你的直觉是对的。

## 2. 我们这边已经做好的（代码侧）

| 文件 | 作用 |
|---|---|
| `config/ads.js` | 6 类广告位 ID 配置，**全空 = 未开通**。一个 ID 只能用于一种类型 |
| `scripts/check-ads-config.js` | 不联网自检：格式 / 跨类型复用 / 拿 OfferID 或网址假冒 |
| `pre-commit` 第 7 道 | 配错就**提交不上去**（刚提交时已实跑） |

**变异测试 4 红 2 绿**（网址冒充 ID / 纯数字冒充 / 同一 ID 复用 / 只有前缀 → 全红；合法 ID 与全空 → 不误判）。

### 为什么没有 `utils/ads.js`（我写了，又删了）

写完自检跑 `validate.js`，**主包体积 1864KB > 预算 1860KB** —— 就超出 4KB。

- 主包硬上限 2048KB，本仓按"留 10% 余量"定的 1860KB；
- 加一个**当前根本用不上**（UV=0、没有广告位 ID）的 5.5KB 封装去挤掉 4KB 预算，
  是拿"看起来做了事"换真实风险。

所以：**保留配置 + 自检（`scripts/` 不进包，零成本），先不打包广告工具**。
等真的要接页面时，把 `utils/ads.js` 和页面改动**一次性加**，那时再核算包体。
这个取舍不是功能缩水，是**不为一根还没通电的电线占主包预算**。

### 我**没有**往页面里塞广告，原因说清楚

- 广告最优的三个位置是：**结算页 banner**、**关卡页激励视频（看广告得一次提示）**、**关卡列表原生模板**。
- 这三个页面（`pages/result/*`、`pages/game/*`）**正被另一条并发改动线在改**，我现在写会覆盖别人的活。
- 次优位置（权益中心、证书页）放广告会**稀释产品的信任感** —— 用户正在看"我得到了什么"，插入广告是在他要走的时候伸手要钱。
  **为一个还没开通的功能去伤现在的产品，不划算。**

## 3. 等页面空出来，接上去怎么改（下面这段**现在就能用**）

### A. 结算页 banner（最稳，打扰最小，不依赖任何封装）

```html
<!-- pages/result/result.wxml，放在按钮下方；wx:if 保证没配置时什么都不渲染 -->
<ad wx:if="{{adBanner}}" unit-id="{{adBanner}}" ad-type="banner" ad-theme="white"></ad>
```

```js
// pages/result/result.js
var ADS = require('../../config/ads.js');
function adUnit(k) {
  var v = String((ADS && ADS[k]) || '').trim();
  return /^adunit-[0-9a-z]{6,40}$/i.test(v) ? v : '';   // 格式不对就当没配
}
Page({
  data: { adBanner: adUnit('banner') }   // 加这一行即可
});
```

### B. 关卡页「看广告得一次提示」（收益最高，但要克制）

接入时我再把封装补上（连同页面一次提交、一起核算包体）。**必须先守住三条**：

1. 只能在**按钮的 tap 回调**里调 `wx.createRewardedVideoAd(...).show()` —— 官方要求点击触发
2. 发奖**只看 `res.isEnded`**：`true` 才发，`false`（中途关掉）不发
3. 官方原文「每个用户每天可观看激励式视频广告的次数有限」→ 不要把核心进度绑在广告上，
   否则用户撞上限额就卡死

⚠️ **红线**：不能写「看广告送酥油灯/送哈达」——
那等于用广告换我们自己的虚拟道具，**绕开了虚拟支付**，属于违规套利。
激励只能换**游戏内的一次提示**这类非卖品。

### C. 原生模板广告（列表页）

`<ad-custom unit-id="...">`，适合关卡列表/护照列表底部，不打断操作。

## 4. 收益：我不给数字，只给口径

- 计价由**竞价**决定，官方不承诺单价。
- 收入 ≈ 曝光量 × 曝光单价 + 点击 × 点击单价，**两者都随行业、季节、用户画像剧烈波动**。
- 所以任何"日均能赚多少"的说法，在没有真实跑过一周之前都是编的。**我不编。**
- 真实做法：开通后先只放 1 个 banner，跑 7 天看后台「曝光/点击/收益」三个数，再决定要不要加激励视频。

## 5. 和虚拟支付的关系（不冲突，但别混）

- 两者可以并存：广告是"没付费意愿的人变现"，虚拟支付是"有付费意愿的人变现"。
- **但一单里不能既收钱又强制看广告**（那是捆绑）。
- 纯虚拟类目会被关闭普通微信支付（D134 已查），**不影响广告**。
- **顺序**：虚拟支付先（无条件门槛，开通即永久可用）；广告后（要 1000 UV，是从 0 到 1 的过程）。

## 6. 你要做的（广告这条线）

1. mp 后台确认**已认证**（流量主的前置）
2. 攒到 **UV ≥ 1000**（这是唯一真门槛 —— 没有内容与传播就没有广告收入）
3. 后台 → 推广 → 流量主 → 开通 → **新建广告位**（banner 先建 1 个够）
4. 复制 ID 填进 `config/ads.js` → `node scripts/check-ads-config.js`
5. 告诉我哪个页面可以用（等并发线落地），我 3 行接上去
