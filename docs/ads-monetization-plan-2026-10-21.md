## 0. 一句话

**广告不是"最好的门路"，是"最不需要用户掏钱"的那条。**
它的天花板是**流量**，不是转化率 —— 而我们现在流量是 0。
**限制也很多，只是限制集中在"开通门槛"和"展示纪律"，不是"资质"。**

顺序建议不变：**先把虚拟支付接通（那是能力，开通就永久可用），广告等有 UV 再接。**

### `utils/ads.js`：D138 删过，D156 已重新落地

**D138 当时的取舍（保留为历史）**：写完自检跑 `validate.js`，**主包体积 1864KB > 预算 1860KB** —— 就超出 4KB。
一个当时根本用不上（UV=0、没有广告位 ID）的 5.5KB 封装去挤掉 4KB 预算，是拿"看起来做了事"换真实风险。
所以只留配置 + 自检（`scripts/` 不进包，零成本），不打包广告工具。

**2026-11-07 复核：这个前提已经消失。** 主包 **1681KB ≤ 1800KB**（`validate.js` §38 实测），余量 119KB。
于是按原计划「连同页面一次性加回」：`utils/ads.js`（5.4KB）已落地，两个页面一起接上，包体重算后仍达标。

### 页面广告：D156 已接好，但**默认完全不渲染**

| 位置 | 实现 | 未开通时的行为 |
|---|---|---|
| 结算页 | `<ad ad-type="video">`；banner 是**运行时退路**（video 没配 **或加载失败**才轮到它）。失败态按位记（`videoFailed` / `bannerFailed`），只 `hidden` 隐藏父容器、不移除组件 | `wx:if="{{adVideo \|\| adBanner}}"` 整块不渲染 |
| 游戏页 | 激励视频「看一段 · 得一次提示」，入口在盘面**下方文档流**（不是浮层，不挡点击） | 只有 `adHintOn && adHintLeft > 0` 才出现；`adHintOn` 需广告真拉取成功 |
| 关卡列表原生模板 | **仍未做**（不想稀释列表的信任感） | — |

> **位置：已按实测改过一次（D156 ⑭）**
>
> 原方案放在**内容末尾**。实测（H5 镜像同构 · 320/360/390/430 四档）：
> 广告位起点 y≈**1500~1576**，而首屏只有 **568~932** → 要下滑 **668~1108px** 才看得到，
> 等于**没有广告**（不是"曝光偏低"，是几乎为零）。
>
> 现改为紧跟**成绩区之后**（y≈**299**）：banner 终点 399、video 终点 499，
> **四档机型首屏全部可见**。揭晓卡 / 收藏 / 分享仍在它后面，「下一课」是固定底栏，不受影响。
> 门禁已加 DOM 顺序判据，把它挪回末尾会判红。
>
> **代价（如实记）**：广告位前移会让**揭晓卡 / 收藏 / 分享整体下移约 100（banner）~200（video）px**，
> 小屏上"揭晓秘境图"要多滑一点才看到。这是拿曝光换的，不是白得；
> 如果日后觉得伤情绪，可以把 **video 换成 banner**（100px，代价减半）而不是挪回末尾。

**没变的三条克制**（原计划里写对的）：
- 广告最优位置的判断不变；次优位置（权益中心、证书页）**仍然不放** —— 用户正在看"我得到了什么"，
  插入广告是在他要走的时候伸手要钱。
- 激励只换**游戏内一次提示**（非卖品），不换酥油灯 / 哈达 / 道具 / 学习得分。
- 每课上限 1 次，核心进度不绑广告；中途关掉不扣次数。

## 3. 当时的接入方案（**D156 已按此落地**，下面代码留作设计依据，不是待办）

### A. 结算页 banner（最稳，打扰最小，不依赖任何封装）

```html
<!-- pages/result/result.wxml，放在按钮下方；wx:if 保证没配置时什么都不渲染 -->
<ad wx:if="{{adBanner}}" unit-id="{{adBanner}}" ad-type="banner" ad-theme="white"></ad>
```

```js
// pages/result/result.js
var ADS = require('../../config/ads.js');
function adUnit(k) {
  var v = String((ADS && ADS[k]) || '').trim();
  return /^adunit-[0-9a-z]{6,40}$/i.test(v) ? v : '';   // 格式不对就当没配
}
Page({
  data: { adBanner: adUnit('banner') }   // 加这一行即可
});
```

### B. 关卡页「看广告得一次提示」（收益最高，但要克制）

**D156 实际实现（`utils/ads.js` + `pages/game/game.js`）**，三条都已由门禁钉死：

1. `show()` **只出现在 `onTapAdHint` 这个 bindtap 回调里** —— 官方要求点击触发；
   `wx.createRewardedVideoAd` 是**页面级单例**，`onLoad` 建、`onUnload` 用 `destroy()` 摘监听。
2. 发奖判据只此一处：`p.resolve(!!(res && res.isEnded))`。
   `isEnded=false` / 回调缺字段 / 拉取出错 / 连点，全部不发；`show()` 失败先 `load()` 重拉再 `show()` 一次。
3. 每课 `adHintLeft = 1`，且**只有完整看完才扣次数**；提示用 `findHintPair()` 在真实盘面上找一手
   （三消查 `swapMakesLine`、配对查同 id），只给两张牌描 3.2 秒金环，不改盘面数据。

⚠️ **红线**：不能写「看广告送酥油灯/送哈达」——
那等于用广告换我们自己的虚拟道具，**绕开了虚拟支付**，属于违规套利。
激励只能换**游戏内的一次提示**这类非卖品。

门禁 `scripts/test-ad-runtime.js` 用假 `wx` 替身真跑「创建 → onLoad → show → onClose → destroy」全链，
37 项断言；`scripts/ci.py` 与 `pre-commit` 都会拦下任何把上面三条改坏的提交（9 项变异测试已验证会翻红）。

### C. 原生模板广告（列表页）

`<ad-custom unit-id="...">`，适合关卡列表/护照列表底部，不打断操作。

## 4. 收益：我不给数字，只给口径

- 计价由**竞价**决定，官方不承诺单价。
- 收入 ≈ 曝光量 × 曝光单价 + 点击 × 点击单价，**两者都随行业、季节、用户画像剧烈波动**。
- 所以任何"日均能赚多少"的说法，在没有真实跑过一周之前都是编的。**我不编。**
- 真实做法：开通后先只放 1 个 banner，跑 7 天看后台「曝光/点击/收益」三个数，再决定要不要加激励视频。

## 5. 和虚拟支付的关系（不冲突，但别混）

- 两者可以并存：广告是"没付费意愿的人变现"，虚拟支付是"有付费意愿的人变现"。
- **但一单里不能既收钱又强制看广告**（那是捆绑）。
- 纯虚拟类目会被关闭普通微信支付（D134 已查），**不影响广告**。
- **顺序**：虚拟支付先（无条件门槛，开通即永久可用）；广告后（要 **UV ≥ 500**，是从 0 到 1 的过程）。

3. 后台 → 推广 / 功能 → **流量主 → 开通**，并**补齐结算 / 财务资料**（不补会影响结算）。
4. 新建广告位，至少各 1 个：`video`（结算页视频）、`banner`（退路）、`rewarded`（激励视频，创建时**必填解锁时长 15 / 30 秒**）。

7. 跑满 7 天后台真实数据（曝光 / 点击 / 收益）再决定加不加广告位 —— **在此之前任何收益数字都是编的，我不给。**
