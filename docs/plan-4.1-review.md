# 4.1 产品系统方案 · 专家评审与落地路线

> 评审对象：《藏字方块 · 产品系统方案 4.1》（四道硬门 + 30天留存引擎 + 合规校正）
> 评审基准：当前仓库 tibetan-match（微信原生小程序 MVP，自检 67/67，已上线 GitHub）
> 结论先行：**4.1 的合规与商业修正在约 80% 的条目上正确且必须采纳；但它的「技术迁移」和「留存引擎」两块与自己定的 Gate 纪律相矛盾，需要修正执行顺序。**

---

## 一、逐项裁定

### 1.1 立刻采纳（无保留）

| 条目 | 裁定理由 |
|---|---|
| 四道硬门（GAME→CULTURE→REGULATORY→BUSINESS） | 正确的开发纪律，采纳为项目宪法 |
| 15分钟核心体验作为 MVP 验收标准 | 完全正确。现有 10 关 MVP 是「内容堆量」，不是「体验闭环」 |
| MD5 防篡改删除 | 正确。客户端生成的 MD5 无安全价值，删除 |
| 数据同步：服务器版本号 + 服务器权威 | 正确。时间戳互覆盖是经典事故源 |
| 高价值数据服务器主导（stamps/coupons/entitlements） | 正确。本地缓存可改，必须服务器验证 |
| onShow 存档降级为最后防线，关键资产即时云存 | 正确 |
| 广告三阶段（A 零广告→B 仅激励视频→C 才测插屏） | 正确，比 4.0 的「上线即挂广告」专业得多 |
| 广告金 ≠ 现金收入，财务模型只计现金 | 正确，这是投资人/合作方一眼能看穿的错误 |
| IAP 作为 platform-specific feature gate | 正确。iOS 虚拟支付政策不稳定，不能写死架构 |
| 内购商品原则：学习免费、表达付费 | 正确，且与品牌调性（有趣·亲切·有文化）一致 |
| 实体护照 / 数字护照订单流拆分 | 正确，物流+虚拟混单是售后灾难 |
| 版号判断不可假设（"无内购≠无版号"） | 正确。本项目含民族文化题材，**恰好落在大流程审批与简化审批的边界上**，必须专项确认 |
| 备案三证拆开（小程序备案 / ICP 许可证 / 版号） | 正确，2023 年后小程序确在备案范围内 |
| 隐私 Capability Matrix（不用不拿） | 正确，且与《个人信息保护法》最小必要原则一致 |
| 分享不得利益诱导 | 正确，微信平台红线 |
| 云开发成本不可假设永久免费 | 正确，CloudBase 套餐 2025-2026 年已多次调整 |

### 1.2 采纳但修正执行顺序（关键反对意见）

**反对 1：先迁移 Cocos，再验证好玩 —— 顺序反了。**

4.1 自己说「如果 15 分钟不成立，1000 关也没有意义」，Gate 1 是第一道门。但 4.1 又要求立刻按 Cocos Creator 小游戏架构重建。矛盾在于：

- Gate 1 验证的是「玩法是否有留存力」，与渲染引擎无关
- 现有 MVP（配对消除 + 文化卡 + 进度）已经可以跑 15 分钟体验测试
- 在好玩未被证明之前投入 Cocos 全量重写，违反 Gate 1 本身

**修正后的顺序**：

```
第一步（1-2周）：现有小程序 MVP 上加齐 15 分钟体验要素
                连击计数 → 特殊方块（1种）→ 护照印记 → 单句发音
                用体验版二维码找 20-50 个真实用户做 Gate 1 测试
        ↓ Gate 1 通过
第二步：Cocos Creator 重建（数据层/音频/Logo/tibetan-text 全部可平移）
        ↓
第三步：Meta 系统（护照/收藏册/地图）按留存引擎分期上
```

**反对 2：留存引擎一次做完 —— 违反分期纪律。**

第十七章列了 12 个系统（每日任务/签到/周主题/稀有掉落/限定关卡/文化等级/护照/地图…）。这是 30 天留存目标态，不是开发清单。按 4.1 自己的五阶段倒推排期：

| 留存阶段 | 需要的系统 | 何时开发 |
|---|---|---|
| Day1-3 形成习惯 | 每日 3 任务 + 7 天签到 | Gate 1 通过后第一批 |
| Day4-7 收藏欲 | 收藏册（单系列 5 卡即可） | 第一批 |
| Day8-14 成长感 | 文化等级 LV1-5（纯经验值） | 第二批 |
| Day15-21 炫耀 | 文化护照 + 分享海报 | 第二批 |
| Day22-30 长期目标 | 七地市地图 + 毕业证书 | 第三批（等 D7 数据） |
| 稀有掉落 80/15/5 | 掉落表 | 随收藏册一起，概率配置先做死 |
| 每周主题 / 每日限定 | 内容运营系统 | P2，等有日活再说 |

**反对 3：云端同步列为 P0 必做 —— 与 Gate 3 未过矛盾。**

P0 清单同时写了「云端同步」和「REGULATORY Gate 未过」。云端同步需要：云环境 + OpenID 静默登录 + 服务器权威逻辑。在主体/类目/备案未确认前，这套东西的建设顺序应调整为：

1. Gate 1 测试期：纯本地存储（现有方案）够用，测试用户可接受
2. Gate 3 明确路线后：OpenID 静默登录 + 云端存档（L0→L1）作为第一朵云
3. 涉及权益/付费时：L2/L3 身份 + 服务器权威全套

**反对 4：立即更名 —— 建议测试后再定。**

「雪域方块 / 雪域探秘」对点击率的假设是对的，但这是可 A/B 的市场问题，不是必须现在拍板的工程问题。改名成本在上线前≈0，上线后很高。建议：Gate 1 测试时用两张落地页测名称点击意愿，拿数据说话。**本仓库当前保留「藏字方块」，更名只改 app.json/文案/Logo 文字层，半天工作量，随时可切。**

### 1.3 需要指出的事实性风险

- **类目风险是本项目的最大单点**：消除玩法 + 藏文 + 宗教文化符号（吉祥结、莲花）。4.1 已正确指出简化审批排除民族宗教题材，但没有给出替代路径。两条腿走路：① 教育叙事（藏文识字启蒙工具，文化卡是内容主体）；② 若走小游戏类目，准备民族文化内容专家审核材料（Gate 2 的母语者审核结论可以直接复用为审核证据）。
- **15 分钟体验表里的「第一次听到藏文发音」**：需要语音资源。藏文 TTS 质量差且发音不标准，必须真人录制（8 个字母 × 1 次发音，成本极低，录完即 Gate 2 的发音证据）。
- **藏文字块合成提前到第二阶段**：同意理由（字母→音节→词的层级天然契合），但提醒：音节结构（基字+上加字+下加字+元音+前后加字）的拼合校验规则本身就是 Gate 2 内容，需要母语者先给出 30-50 个 MVP 词表再开发。

## 二、现有代码资产处置表

| 资产 | 处置 | 说明 |
|---|---|---|
| `data/elements.js` `cards.js` `levels.js` | **保留并迁移** | 纯数据，Cocos 直接 require/JSON 化 |
| `utils/tibetan-text.js` | **保留并迁移** | tsheg 断行算法与引擎无关，Cocos Canvas 同样适用 |
| `utils/audio.js` + 4 个 WAV | **保留并迁移** | 音效资产引擎无关 |
| `images/logo-*.png` + 生成脚本 | **保留** | 品牌资产，与引擎无关 |
| `utils/storage.js` | 保留至 Gate 1 测试结束 | 云同步上线后被替代，但本地缓存层仍作 L0 |
| `utils/icons.js`（简笔图标绘制） | 迁移时重估 | Cocos 下改为矢量绘图或序列帧 |
| `pages/` 三个页面 | Gate 1 后废弃重写 | WXML/WXSS 不迁移，但 UI 交互规格可作 Cocos 还原基准 |
| `scripts/validate.js` | **保留并扩展** | 迁移 Cocos 后改为校验 JSON 配置 + 数据一致性 |
| 祝福卡 Canvas 绘制 | Gate 1 后重写 | 绘制逻辑平移，需重做小程序码部分 |

**结论：重写损失可控。约 40% 代码资产（数据层+工具层+音频+品牌）可平移，废弃的是 UI 层——而 UI 层本来就要按 15 分钟体验重做。**

## 三、修订后的 P0 清单（Gate 1 冲刺，两周内）

1. 连击系统：连续消除计数 ×N 提示 + 连击音效（体验表 4:00 节点）
2. 特殊方块 1 种：金色字母（消除得双倍积分），先用现有元素染色实现
3. 藏字块组合原型：ཀ+ཨ = ཀཨ？——**否决此实现**，改为：基础音节拼图（母语者给词表后定），Gate 1 阶段只做「合成动画占位」
4. 文化护照印记 v0：通关即得拉萨印章，本地存储，首页显示 1 个印记位
5. 8 个字母真人发音：录音 + 点击牌面播放（体验表 1:00 节点）
6. 新手引导 3 步：第一次点击提示 → 第一次配对提示 → 完成
7. 15 分钟埋点：每个体验节点的到达时间记录（本地即可，测试后导出）
8. Gate 1 测试包：体验版二维码 + 20-50 名测试用户 + 反馈问卷

**明确不做（Gate 1 期间）**：云端、登录、广告、Cocos 迁移、更名、留存引擎任何系统。
