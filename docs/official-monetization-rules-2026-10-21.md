## 0. 先给结论（一张表看完）

| 变现方式 | 官方允许吗 | 硬门槛（官方原文） | 我们需要什么 | 现在能做吗 |
|---|---|---|---|---|
| **广告（IAA）** | ✅ 允许 | 流量主开通：**累计独立访客 UV ≥ 500 且无违规** | 先有 500 个真人用过 | ❌ 用户数=0 |
| **充值/打赏/虚拟礼物（IAP）** | ✅ 允许，但**必须**走官方"小程序虚拟支付" | 个体户：**已认证 + 主体为个体工商户 + 信息完备**；小游戏路径另需**版号** | 认证（300 元）+ 开通虚拟支付 | ⚠️ 技术上可开，**类目一致性有风险** |
| **实物（藏香）** | ✅ 允许 | 微信小店类目卡住（见 D133）；小程序自建+微信支付可绕 | 商户号 + 服务器 | ⚠️ 有条路，但要建收银台 |
| **"送礼"到底算哪种** | ⚠️ 分两种，不能混 | 送**虚拟**礼物（哈达/酥油灯）→ 属虚拟支付；送**实物** → 属电商 | 看你送什么 | 我们现在送的是虚拟的 |

**一句话**：三种都能做，但**门槛顺序是 使用者数 → 认证与类目 → 收银台**。
现在卡在第一步（0 用户）和第二步（账号还没注册）。

## 1. 一个决定性事实：这个项目**还没注册账号**

`project.config.json` 里 `appid: "touristappid"`（游客模式）、`compileType: "miniprogram"`。

**这意味着类目还没锁死 —— 现在正是决定走"小程序"还是"小游戏"的唯一窗口。** 官方规则：

> 「一级类目，不支持修改，且**小游戏账号只有"游戏"这个类目（注册时勾选），无法更换或删除，如选择错误只能重新注册**」
> —— 微信官方《类目设置》[^1]

> 「2.1.3 你需根据实际提供服务范围慎重选择服务类目，**一旦你选择了游戏类目，该类目将不可修改变更为其他小程序类目**」
> —— 微信官方《常见拒绝情形》[^2]

> 「2.1.1 小程序**服务类目所对应的页面中的核心内容必须与该类目一致**」
> —— 同上[^2]

**这三条合起来的意思**：
- 选了「游戏」→ 就是小游戏账号，**永久不能改成别的类目**
- 选了「教育/文化」→ 页面核心内容必须真的是教育/文化，**不能是一个纯游戏**

## 2. 广告变现（IAA）：允许，不需要版号，但要先有 500 个用户

### 2.1 官方门槛

> 「**开通条件：小程序累计独立访客（UV）500 以上，且无违规记录**，即可开通流量主功能。」
> —— 微信开放社区官方公告[^3]

### 2.2 能接哪些广告（官方组件清单）

Banner、插屏、**激励视频**、视频广告、视频前贴、原生模板、封面广告、支付订单详情页广告。

**关键**：激励视频在小程序（非小游戏）路径下**有官方开发文档**——
`developers.weixin.qq.com/miniprogram/dev/framework/open-ability/ad/rewarded-video-ad.html`[^4]
→ **普通小程序可以接激励视频**（2018 年"非小游戏只能 Banner"的说法已过时；
2019 年官方公告：视频广告与前贴已面向**非游戏类小程序**全量上线[^5]）。

### 2.3 小游戏做纯广告（IAA）**不需要版号**（这条最反直觉，但有原文）

官方「小游戏备案前置审批指引」把游戏分两种通道[^6]：

| 通道 | 材料 | 要版号吗 |
|---|---|---|
| **情况一 IAP**（要开虚拟支付） | **网络游戏出版物号核发单（必填）** + 软著 + 运营/著作权授权书 + 自审自查报告 + 内容一致承诺函 | 🔴 **必须** |
| **情况二 IAA**（当前及未来都不开虚拟支付） | 代备案授权书 + **著作权自我声明** + 游戏自审自查报告 | 🟢 **不需要** |

> 情况二额外要软著的只有两种情形：「游戏名称含有英文、或"软件"字样」「涉及相关品牌、公众人物合作等」[^6]

### 2.4 广告的真实收益逻辑（不粉饰）

- 广告费按曝光/点击结算，**单价由平台与竞价决定，官方不承诺任何数字** → 我不给你"日均多少钱"的估算，那是编的。
- 前提是**有留存**。UV 500 只是"能开通"的门槛，不是"能赚钱"的门槛。

## 3. 充值 / 打赏 / 虚拟礼物（IAP）：允许，但有两条完全不同的路

### 3.1 官方定义：这些东西**必须**走虚拟支付，不许绕

> 「开发者在小程序内提供的虚拟商品（包括**虚拟货币、解锁功能、订阅内容、付费功能、打赏、购买虚拟礼物**等），
> 购买和支付**均需接入小程序虚拟支付**；**不得引导至 app、公众号、h5、个人号、网站完成支付**。」
> —— 《虚拟支付业务运营指南》[^7]

> 「形态二：虚拟道具与充值 —— 用户在小程序内购买**虚拟代币、游戏道具、虚拟礼物**、虚拟装扮等……
> 示例：购买积分/钻石；直播打赏虚拟礼物；购买虚拟玫瑰/装扮道具；**付费抽奖/拆盲盒获得虚拟奖品**」[^7]

**直接把我们的四个道具对上号**：酥油灯、哈达、祝福卡、藏文名字打赏 = **虚拟礼物 / 打赏** → 必须走虚拟支付。
我们现在的 `utils/payment.js` 走的就是官方虚拟支付（米大师），**方向是对的**（D90 已记）。

### 3.2 我们（个体户）能不能开通？—— 官方条件只有三条

| 条件 | 说明 |
|---|---|
| 已认证小程序 | 主体类型需为**已认证**的小程序 |
| 企业 / 事业单位 / **个体工商户** | 小程序类型需为企业、事业单位或个体工商户 |
| 主体信息完备 | 信息若有缺失，请通过平台提供的修改链接修正 |

—— 《虚拟支付：企业、个体户》[^8]
**该页全文没有提"类目""备案""版号""软著"**（我逐字核对过）。

### 3.3 但**小游戏**路径要版号（这就是"说法不一"的来源）

> 资质审核（IAP）材料：「**网络游戏出版物号核发单（必填）**」「计算机软件著作权登记证书（必填）」
> —— 《资质审核(IAP)》[^9]

> 「开通虚拟支付的网络游戏企业必须自行前往**中宣部实名认证系统**完成企业注册、添加游戏、渠道绑定……
> 游戏版号：需与中宣部实名认证系统中的游戏版号一致，为 **ISBN** 开头的版号」
> —— 《微信小游戏接入中宣部实名认证系统流程指引》[^10]

**所以**：
- 说「充值能做」的人，通常指**小程序**（个体户可开虚拟支付）
- 说「充值要版号」的人，通常指**小游戏**（IAP 必须版号）
- **两个人说的都对，只是说的不是同一个东西。**

### 3.4 费率：官方给了的才写

- 个人主体：**Android 等 1% 腾讯技术服务费 / iOS 12% Apple 佣金**（《虚拟支付：个人》明文）[^11]
- 企业/个体户：官方只写「按一定费率收取技术服务费」「扣除 Apple 佣金」，**未给数字**[^8] → **我不编，以后台显示为准**

### 3.5 一条容易被忽略的雷：虚拟支付会**关掉**你的普通微信支付

> 「若小程序仅包含以上虚拟类目，平台将**关闭该小程序在安卓及其余非 iOS 系统的普通微信支付能力**，
> 需调用小程序虚拟支付能力进行交易……」
> 「部分小程序同时包含虚拟商品和实物商品（如在线课程赠送教材）将被认定为虚拟支付，**建议拆分为两笔交易分别处理**。」
> —— 《虚拟支付业务运营指南》[^7]

→ 这对卖藏香有直接影响：**虚拟礼物和实物商品必须分成两笔交易**，不能一单混着收。

## 4. "送礼变现"到底算什么：把混淆点拆开

| 你听到的说法 | 实际指向 | 官方定性 |
|---|---|---|
| "送礼物能赚钱" | 用户买**虚拟礼物**送给朋友（我们的哈达/酥油灯） | **虚拟支付**（打赏/虚拟礼物）→ 必须接虚拟支付 |
| "送礼能赚钱" | 用户在你这买**实物**寄给朋友 | **电商**（微信小店 / 自建支付），不是虚拟支付 |
| "收礼物抽成" | 平台从别人的交易里抽佣 | 需**平台类目 + 增值电信业务经营许可证**（我们不是平台，也不该做） |

**我们的 D113「送祝福礼物」属于第一种** —— 虚拟礼物，走虚拟支付，**不是电商**。
之前如果谁把它当"电商"设计，方向就错了。

## 5. 国内服务器 + 域名：官方要求逐条（这是"落地"那部分）

### 5.1 域名（小程序官方《网络》文档原文）[^12]

| 要求 | 原文 |
|---|---|
| 协议 | 「域名只支持 `https` 和 `wss` 协议」 |
| 备案 | 「**域名必须经过 ICP 备案**」 |
| 不能是 IP | 「域名不能使用 IP 地址（小程序的局域网 IP 除外）或 localhost」 |
| 端口 | 可配端口（`https://myserver.com:8080`），但「配置后只能向该端口发起请求」，不配端口时**连 443 都不能带** |
| 父域名 | 「**不支持配置父域名，使用子域名**」 |
| 证书 | 「HTTPS 证书必须有效…部署证书的域名必须与证书颁发域名一致…**iOS 不支持自签名证书**」 |
| TLS | 「**TLS 必须支持 1.2 及以上版本**」 |
| 禁区 | 「`api.weixin.qq.com` 不能被配置为服务器域名」；AppSecret 必须放服务器 |
| 配置位置 | 「小程序后台-开发-开发设置-服务器域名」，四类：request / uploadFile / downloadFile / socket |
| 例外 | 用**微信云托管**做后端「则**无需配置通讯域名**」（走私有协议 `callContainer`） |

### 5.2 小程序本身也要备案（这是另一件事，别和域名备案混）

> 「自 **2023 年 9 月 1 日**起，微信小程序**须完成备案后才可上架**；若已上架，请于 **2024 年 3 月 31 日**前完成备案」
> —— 微信官方备案指引[^13]

流程：平台初审（1-2 工作日）→ 工信部短信核验（24 小时内，12381）→ 通管局审核（1-20 工作日）。

### 5.3 落地清单（按顺序，别乱）

1. 注册小程序主体（个体户营业执照）→ **选类目**（见 §6，这一步锁死，不能回头）
2. 微信认证（300 元）
3. **小程序备案**（工信部，走 mp 后台）
4. 买域名 → **ICP 备案**（在云厂商提交，7-20 工作日）
5. 服务器部署 `server/` + 配 HTTPS 证书（TLS 1.2+，非自签）
6. mp 后台配服务器域名（子域名，四类都配齐）
7. 上传代码 → 提审 → 发布

> 想省掉 4/5/6：用**微信云托管**（官方明说无需配域名）。但小程序备案仍然要做。
> **这条我不替你选** —— 云托管省事但有绑定，自建域名灵活但要备案。见 §7 我给的建议。

## 6. 决策树：三种路线只能选一条（因为类目不可改）

```
你现在还没注册账号（appid=touristappid）→ 还有得选

├─ A. 注册「小游戏」（一级类目=游戏，终身不可改）
│    ├─ 纯广告（IAA）：不需要版号 ✅   但拿不到虚拟支付（情况二承诺"未来也不开"）
│    └─ 要内购（IAP）：必须版号 ❌     个体户基本拿不到
│    → 适合：只做广告、不卖任何东西
│
├─ B. 注册「小程序」（非游戏类目，可改）
│    ├─ 广告：UV 500 后可开 ✅
│    ├─ 虚拟支付：个体户可开 ✅（官方三条条件）
│    ├─ 实物（藏香）：自建微信支付 ✅
│    └─ 风险：核心玩法若是"游戏"，与类目一致性冲突 ⚠️
│    → 适合：想同时做广告 + 虚拟礼物 + 实物
│
└─ C. 两个账号都注册（一个小游戏做广告引流，一个小程序做交易）
     → 成本翻倍、内容要拆两套，不推荐现在做
```

### 我的明确推荐（你仍可推翻）

**走 B：注册「小程序」，类目选「教育 / 文化」方向 —— 理由是产品本身撑得住，不是话术。**

我们不是"纯游戏"：`data/learning.js` 有 **150 课藏文课程**（字母/拼读/词汇 + 音频），
配对消除只是**学习形式**。类目报「教育」或「文化」，页面核心内容确实是课程，
**2.1.1「类目与核心内容一致」这一条才站得住**。

- 广告：等 UV 500，先做内容与传播
- 虚拟礼物：个体户开虚拟支付（酥油灯/哈达/祝福/名字）
- 藏香实物：走 D133 的自建支付路线，**与虚拟礼物分成两笔交易**（§3.5）

**不推荐 A**：小游戏 IAA 虽然不要版号，但拿不到虚拟支付、也卖不了实物，
等于把我们已经做好的礼物/商城全部废掉。
