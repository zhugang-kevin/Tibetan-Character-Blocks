# H5 重构会不会拖累多端上线？（架构回答，2026-10-21）

> 结论先说：**不会 —— 前提是 H5 只承担"共享引擎 + 一个薄壳"，不承担产品本身。**
> 如果 H5 变成"只给 H5 用的玩法"，那才是真的做成了独立站，而且四端各养一套，必死。

---

## 一、你担心的两件事，分开看

| 你的担心 | 实际情况 |
|---|---|
| 「H5 重构会不会影响上线」 | **取决于 H5 里装的是什么**。装引擎 → 是地基；装玩法 → 是分叉 |
| 「H5 是不是变成独立站」 | **如果 H5 自己实现了玩法逻辑**，是的。**如果 H5 只是引擎的一个壳**，不是 |

**判断标准只有一条**：改一个匹配规则，是**改一处**，还是**改四处**。

---

## 二、能共享的 / 不能共享的（这条决定架构）

### ✅ 可以共享（纯 JS、不碰平台 API）
- `utils/match3.js`（匹配、连锁、特效、洗牌、目标模型）
- `utils/board.js`（生成、下落、补池）
- `data/*`（关卡、内容、字库）
- 得分规则、胜负判定、种子/挑战 ID

> 这些**今天就已经是纯函数**，没有一行 `wx.` —— 这是之前分层的成果。

### ❌ 绝对不能共享（每个平台自己的一套）
| 能力 | 微信 | 抖音 | 快手 | H5 |
|---|---|---|---|---|
| 登录 | wx.login | tt.login | 快手登录 | 无（或自建）|
| 存储 | wx.setStorage | tt.setStorage | 各自 | localStorage |
| **支付/打赏** | **微信虚拟支付/米大师** | **抖音钻石/虚拟支付** | **平台支付** | **第三方支付** |
| 分享 | 小程序卡片/朋友圈 | 视频挂载/群 | 平台分享 | 链接 |
| 录屏 | 无原生 | 抖音录屏 | — | 无 |

**关键事实**：**打赏必须在各平台各自的支付通道里完成。** 你在 H5 里收的钱，和微信/抖音里的钱是**三个不同账户、三套结算**。
不存在"H5 收一次、四端通用"这条路 —— 那既违反平台规则，也做不成。

---

## 三、正确的组织方式：一个引擎 + 四个薄壳

```
        ┌─────────────────────────────────┐
        │  共享层（纯 JS，无平台 API）      │
        │  match3 / board / data / 规则    │
        └───────────────┬─────────────────┘
                        │
   ┌────────────┬───────┴───────┬────────────┐
   │ 微信小程序  │  抖音小程序    │ 快手小程序  │   H5
   │ 壳：登录    │  壳：登录      │ 壳：登录    │ 壳：无登录
   │ 支付/分享   │  支付/录屏     │ 支付/分享   │ 第三方支付
   └────────────┴───────────────┴────────────┘
```

**薄壳的职责只有一件**：把平台能力翻译成引擎认得的接口。
引擎**永远不 import 任何平台 SDK**。

---

## 四、H5 在多端战略里到底是什么角色

| 角色 | 是 / 否 |
|---|---|
| 共享引擎的**开发与测试载体** | ✅ 是（改引擎先在 H5 验，最快）|
| 微信/抖音**站外**的低门槛试玩页 | ✅ 是（但要认清：站外打开率低，不等于分发）|
| 产品的主要发行渠道 | ❌ 不是 |
| 打赏收入的来源 | ❌ 不是（各平台内各自收）|

**所以 H5 重构不会拖累上线 —— 只要它是"引擎的壳"。**
反过来：如果 H5 里写了只有 H5 才有的玩法（比如 H5 专属关卡、H5 专属动画），**那才会四端分叉**。

---

## 五、你现在该做的三件事（按顺序）

1. **把平台调用收口成适配层**：现在 `utils/` 里已经有不少 `wx.` 直调（storage / audio / tracker / sync）。
   要把它们收成 `platform.{login,storage,pay,share,audio}` 五个接口，H5/抖音/快手各写一份实现。
   → **这件事不做，后两端接入时会把引擎改烂。**
2. **H5 只做引擎的验证壳**：先跑通"相邻交换 + 连锁 + 特效 + 胜负"，不做 H5 专属内容。
3. **打赏按平台分三套**，共用"礼物配置 + 订单状态机 + 战报"，**不共用支付通道**。

---

## 六、必须标注待核验的部分（不猜）

以下都需要在**各平台后台与当日官方文档**核实，我没有替你确认：

- 快手小程序是否有**虚拟支付/打赏**能力，开放条件是什么
- 抖音小程序（非小游戏）能否做**道具打赏**，是否需要版号
- 微信小程序**工具类目**下能否用虚拟支付（此前查到"已认证 + 企业/个体户 + 信息完备"，但需后台确认）
- 三端**分享回流**的具体参数与限制

> 这三条直接决定"打赏能不能做成"，**不能凭经验回答**。

---

## 七、一句话回答你

**H5 重构不是独立站，是引擎的壳。**
**扩散要靠各平台自己的分享通道，不是靠一个链接走天下。**
**打赏要按平台收三份，不可能一份通吃。**

风险不在技术，在**边界**：引擎和壳有没有分开。现在分开了一半（`utils/` 是纯的，`pages/` 里有 `wx.` 直调），**该把那一半补完**。
