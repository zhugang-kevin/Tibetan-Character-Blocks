## 二、核心矛盾：学习和刺激不是对立的

**「点两张相同的」本身没错 —— 它认知负荷低，适合学字母。**

**错的是它没有任何「赢的感觉」。** 对比一下：

| 维度 | 真实消消乐 | 我们（配对） |
|---|---|---|
| 即时反馈 | 交换成功有弹跳、有音效、有粒子 | **点了就消失，无声无光** |
| 连击 | 连锁触发 combo 倍率、语音播报 | **没有** |
| 长连奖励 | 4连+20、5连+50，出特殊道具 | **没有** |
| 目标感 | 顶部有「目标 / 分数 / 步数」三条进度 | **只有一行小字** |
| 紧张感 | 步数快没了，屏幕边缘发红 | **没有** |
| 成就感 | 过关结算有星级、有排名 | **有结算但很素** |

**结论：不是玩法错了，是「反馈层」全空。**

## 三、方案：保留配对，把反馈层按消消乐的规格补齐

### 3.1 保留什么

✅ **点两张相同的牌**（学习认知负荷最低）
✅ 每关的字母范围（现有 150 课配置）
✅ 现有的池感知重洗（`reshuffle`，这块本来是对的）

### 3.2 补齐什么（按消消乐的反馈规格）

#### ① 顶部 HUD 三条（解决"只占 40% 高"）

```
┌────────────────────────────┐
│ 第 3 课   目标 18 对        │  ← 关卡 + 目标
│ ████████░░░░  12/18        │  ← 进度条
│ 步数 8/16   ●●●           │  ← 步数（耗尽前变红闪烁）
└────────────────────────────┘
       [ 6×6 或 6×7 盘面 ]
┌────────────────────────────┐
│ 连击 x3  分数 240           │  ← 连击 + 分数
│  [寺庙图慢慢揭开]            │  ← 秘境图缩成底部一条
└────────────────────────────┘
```

**这才是真实消消乐的版式：盘面占中间 55–65%，上下是 HUD。**
**不是"把盘面拉大"，是"给盘面配上下文"。**

#### ② Combo 连击（情绪价值核心）

| 连击数 | 反馈 |
|---|---|
| 2 连 | 屏幕轻微震动 + 短音 |
| 3 连 | 金色粒子 + 数字弹出「x3」+ 藏语短音 |
| **4 连** | **标题级播报**（参照消消乐的 "Sweet!"）→ 用藏语吉祥词 |
| **5 连以上** | **全屏金色光环 + 专属音效** |

**这是"刺激"的来源。** 没有这个，配对永远是"点掉一对，点掉又一对"。

#### ③ 长连奖励（数字）

| 一次消除的对数 | 额外奖励 |
|---|---|
| 1 对 | 基础分 |
| 连续 2 对（无失误）| ×1.5 |
| 连续 3 对 | ×2 |
| 连续 4 对以上 | ×3 + 屏幕特效 |

**这就是你说的「四个爆破」在配对玩法里的等价物。**

#### ④ 反馈三件套（每个消除必须有）

```
① 视觉：牌爆成粒子，中心闪白一下
② 触觉：wx.vibrateShort（轻）/ 连击时 heavy
③ 听觉：短促的木鱼/铃声（已有 38 个音频资产，挑合适的）
```

**三条缺一不可。** 现在只有第 ① 条的"消失"，没有爆、没有震、没有声。

#### ⑤ 步数压力（紧张感）

- 步数 ≤ 3 时：**顶部 HUD 变红 + 缓慢脉冲**
- 步数归零：**不是直接失败**，弹「再给 3 步？」（看广告或虚拟支付）
- **这是消消乐的标准做法，也是变现口**

### 3.3 150 座寺庙（每关背景）

**这是这次必须落地的事，不能再拖。**

#### 数据结构（强制带来源）

```js
{
  level: 1,
  name: "大昭寺",
  tibetan: "ཇོ་ཁང་",
  county: "拉萨市城关区",
  sect: "格鲁派",
  founded: "647 年",
  source: "官方来源 URL",     // 没有这个字段，条目不入库
  queriedAt: "2026-10-24",
  img: "/images/temple/001.webp",
  imgCredit: "图片来源与授权说明"  // 没有这个，图片不入库
}
```

#### 呈现方式

```
每关开始时：寺庙图完整显示 2 秒 → 淡出成"模糊底纹"
对局中：每消一对，揭开该图的一小块（现有 reveal 机制）
通关时：整幅寺庙清晰浮现 + 名称 + 藏文 + 一句介绍
```

**这样寺庙不只是"背景"，而是"奖励"** —— 每过一关解锁一座，150 关集满就是一本西藏寺庙图鉴。

#### 数量与进度

| 阶段 | 数量 | 状态 |
|---|---|---|
| 现有 | 10 张（风景，非寺庙）| 需替换 |
| 第一批 | **30 座**（西藏，带官方来源）| **我来查** |
| 第二批 | 30 座（西藏 + 青海）| 待定 |
| 完整 | **150 座** | 需要照片来源 |

**照片来源是独立问题**（版权），我会把数据先做齐，图片位留占位符。

## 四、执行顺序（这次按依赖排，不按"看起来快"排）

```
第 1 步：统一屏幕契约
  └ 定义一套"手机满屏"规则（100dvh + safe-area + 不滚动）
  └ 用它改首页 / 游戏页 / 结算页
  └ 用 4 个机型验证（375/390/412/430）

第 2 步：游戏页 HUD
  └ 顶部：关卡 + 目标 + 进度条 + 步数
  └ 底部：连击 + 分数 + 寺庙图条
  └ 盘面居中，验证"满屏不滚动"

第 3 步：反馈三件套
  └ 粒子爆炸 + 震动 + 音效
  └ 连击播报（2/3/4/5 级）

第 4 步：150 寺庙数据
  └ 先做 30 座（带来源）
  └ 你核对后扩到 150

第 5 步：图片防重复
  └ 加一条构建期检查：同一图片路径不得在同一页面出现两次
  └ 这条检查能防住"图片重叠"再发生
```
