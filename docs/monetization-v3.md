# 藏字方块 · 商业化方案 v3：三条禁区的替代解法

> 更新：2026-10-04 · 关系：本文是 [`business-model-v2.md`](business-model-v2.md) 的修订与扩写，并**更正** v2 §0.2 与 [`release-and-monetization.md`](release-and-monetization.md) §二.3 中关于「虚拟支付不可行」的结论。
> 前置：[`merchant-system-review.md`](merchant-system-review.md)（技术合规评审）

---

## 0. 结论先行（三句话）

1. **三条红线不是三条孤立的路，是同一个病根的三种症状**：都想让「钱」或「虚拟物」在你的小程序里**经手 / 落地**。所以解法不是逐条绕，而是换三个东西：**换「卖什么」、换「钱怎么走」、换「主体与工具」**。

2. **重大更正：内购线其实可以重开。** 你给的前提「虚拟支付 = 个体户/企业 + 已认证**小游戏** + **版号** + 软著自审报告」——那是**小游戏**的规则。**小程序（非小游戏）的虚拟支付是另一条通道**，2026 年官方页明确只要求「已认证 + 企业/事业单位/个体工商户 + 信息完备」，**没有版号要求**；个人主体也已开放（限「工具」类目、月限额 10 万）。iOS 端 2025-11 苹果与腾讯达成和解后已打通（走苹果 IAP，苹果抽 15%）。

3. **另外两条（原生分账、二清）确实关死**，但各有合规替代：分账 → **持牌机构清算**或**升级公司做服务商**；二清 → **资金全程不经过你**（C 端钱进商家/你自己的商户号，B 端钱才是你的服务费）。

---

## 1. 重大更正：把「小游戏」和「小程序」分开看

这是整套方案的地基。绝大多数「虚拟支付不可行」的结论，都栽在把这两条通道混为一谈。

| 维度 | 小游戏 · 虚拟支付 | **小程序 · 虚拟支付（2026）** |
|---|---|---|
| 主体门槛 | 企业 + 已认证小游戏 | **已认证 + 企业/事业单位/个体工商户**（个人另开通道） |
| 版号 | **必须** | **不需要** |
| 软著自审报告 | 必须 | 不需要 |
| 服务类目 | 游戏 | 文娱 / 工具 / 社交 / 资讯 / 深度合成 / **教育（付费课程）** 等 |
| iOS | 长期封闭 | **2025-11 已打通**，走苹果 IAP |
| 结论 | ❌ 关闭（拿不到版号） | ✅ **可开** |

**官方原文（小程序·企业/个体户，2026-10-04 实检）**：开通条件只有三条 —— 「已认证小程序」「小程序类型需为企业、事业单位或个体工商户」「主体信息完备」。官方页**未列版号要求**。

**iOS 侧的破冰**：2025-11-14 苹果推出「小程序合作伙伴计划」（Mini Apps Partner Program），把小程序 IAP 抽成从 30% 降到 **15%**；微信随即公告将在 iOS 端小程序接入苹果虚拟支付。分成结构是 **苹果 15% / 腾讯 0 / 开发者 85%**。

> ⚠️ **但这不意味着可以躺着开**。三个真实约束：
> ① **类目必须匹配**——后台类目不对，虚拟支付入口根本不出现；
> ② **必须是「教育/文化」而非「游戏」**——若被判为游戏内容，你又被推回「小游戏·需版号」的死路。**「去游戏化」改造从「为了过审」升级为「为了能开虚拟支付」，优先级不变但理由更硬**；
> ③ **必须有服务端**（签名 + 回调 + 发货 + 查单）——这突破本项目「不做后端」的原始红线，需用云开发兜住。

## 2. 逐条重划边界

| # | 你的结论 | 2026 真实边界 | 能否重开 | 替代解法 |
|---|---|---|---|---|
| 1 | ❌ 小程序内虚拟内购 | 那是**小游戏**规则。**小程序**虚拟支付无需版号，个体户/企业/个人均开放 | ✅ **可重开** | **引擎 A** |
| 2 | ❌ 微信原生分账自动抽佣 | ✅ 结论正确：需企业/服务商资质，接收方须**企业**独立商户号，单笔 **30% 上限**，个人/个体户不可作接收方 | ❌ 不能再开 | **引擎 D / E** |
| 3 | ❌ 代收交易款再转给商家 | ✅ 结论正确，且是**绝对禁区**（无证二次清算，央行银发〔2016〕217 号文） | ❌ **永不可做** | **引擎 B / C / D / E**（资金永不归集） |

**记住一句话**：监管禁的是「**你没有支付牌照却干了清算的活**」，不是禁你赚钱。**只要资金不归集、不拆分，你收多少钱都不违法。**

## 3. 五条变现引擎（总览）

| 引擎 | 卖什么 | 资金来源 | 资金是否经过你 | 主体 | 费率/成本 | 与项目匹配 |
|---|---|---|---|---|---|---|
| **A · 虚拟内容付费** | 进阶课程包、证书增值、文化专题、会员 | **C 端用户** | ✅ 是（合规，你就是收款方） | 个体户/企业（个人限工具类目，月 10 万） | 平台技术服务费（公开口径约 1%，以后台为准）+ iOS 苹果 15% | ★★★★★ |
| **B · 实物文创电商** | 字帖、卡片、印章、藏香、唐卡印刷品、残疾人手工艺品、**学习礼盒** | **C 端用户** | ✅ 是 | 个体户/企业 | 普通微信支付 0.6%~1%（小微 9 折至 2027-09-30） | ★★★★★ |
| **C · B2B 内容授权 / SaaS** | 藏文排版引擎 + 内容库 + 证书体系授权给文旅/博物馆/学校 | **B 端机构** | ✅ 是（服务费） | 个体户/企业（可开票） | 无平台抽成 | ★★★★☆（天花板最高） |
| **D · 到店导流服务费** | 核销券带来的到店（**定额**计费） | **B 端商家** | ❌ 否（交易额归商家） | 个体户 | 无 | ★★★☆☆ |
| **E · 持牌清算 / 升级公司** | 真做「平台」时的资金方案 | — | 视方案 | 公司（服务商）/ 持牌机构 | 见 §4.5 | ★★☆☆☆（二期） |

> **A + B 是双引擎主力**：A 收虚拟的钱（高毛利、零边际成本），B 收实物的钱（有履约、有溢价、能叠公益叙事）。C 是天花板。D 是防守性的（守住已验证的商家关系）。E 是期权。

## 4. 引擎详解

### 4.1 引擎 A · 虚拟内容付费（**最优先**）

**为什么最优**：边际成本≈0，不需要进货、不碰物流、不涉及二清；且证书/成长阶梯体系已经做好了。

**卖什么（必须保持「教育/文化」外壳）**：

| 想法 | ❌ 游戏化命名（危险） | ✅ 教育化命名（安全） |
|---|---|---|
| 解锁后续阶段 | 「解锁第 2 关」 | 「进阶课程包 · 第二阶段」 |
| 证书 | 「成就勋章」 | 「藏文启蒙学习证书（电子版）」 |
| 内容合辑 | 「道具礼包」 | 「文化专题包 / 发音精讲课」 |
| 会员 | 「VIP 去广告」 | 「全阶会员：12 阶段 + 专属证书 + 打印版文化卡」 |

**资金流（合规）**：

```
用户付费 → wx.requestVirtualPayment → 微信虚拟支付商户号（你的） → T+3 结算提现
                    │
                    ├─ 服务端生成订单 + 双签名（paySig / signature）
                    ├─ 支付回调 / 主动查单 双通道兜底
                    └─ 校验通过 → 发货（解锁权益）
```

**规则要点**：
- 开通入口：MP 后台 → **支付与交易 → 虚拟支付** → 开通（生成**独立的二级商户号**，与普通微信支付商户号隔离、账单独立）
- 结算：安卓等终端 **T+3**；iOS 由苹果结算（自然月后 45-60 天）
- iOS 前置：需配置**小程序简称**；用户需 iOS 15+ 且微信 8.0.68+
- 代币兑换比例**一经发布不可修改**——MVP 建议**直接用「道具模式」（商品直购）**，别碰代币

**技术红线**：签名**必须在服务端**（前端生成签名会被风控拦截）→ 用云开发云函数承载 `signData` 组装、`paySig`/`signature` 计算、回调验签与发货。

**混合玩法（很有用）**：把虚拟权益**实体化**可以改走普通支付 —— 卖「**藏文启蒙学习礼盒**（实体字卡 + 印章 + 配套线上课程）」，小程序内支付的是含实物的套餐，走引擎 B 的普通商户号。审核更稳，且客单价更高。

---

### 4.2 引擎 B · 实物文创电商（自营收 C 端钱）

**为什么必须做**：这是唯一「完全合规、钱 100% 进你自己、不受 30% 上限限制」的 C 端收款方式。虚拟支付有类目与审核不确定性，实物支付没有。

**卖什么**：
- 藏文文创：儿童识字卡、字帖、印章套装、明信片、藏香、唐卡印刷品、祝福卡（现有祝福卡可直接商品化）
- **残疾人手工艺品**（承接 v2 的公益线，但**必须有实物履约**）
- **学习礼盒**（实体 + 线上课程捆绑，见上）

**资金流**：用户 → `wx.requestPayment` → **你的个体户商户号** → T+1 到账。全程归你，无争议。

**合规要点**：
- 经营类目 = 营业执照经营范围 = 实际商品，**三者必须一致**（否则驳回/下架）
- 食品（藏香若涉食用需注意）、出版物（字帖若含 ISBN 需出版资质）等特殊品类要补专项资质
- **代销残疾人手工艺品**：只做**一级**，不得发展多级分销（§5.9），不得用「募捐 / 捐款 / 慈善募捐」表述（《慈善法》）
- 若要卖别人的货，优先 `wx.navigateToMiniProgram` 跳对方小商店（微信小商店），你不碰货、不碰钱

---

### 4.3 引擎 C · B2B 内容授权 / SaaS（天花板最高）

**为什么重要**：不依赖 C 端日活，现金流稳定，且**完全绕开小程序支付的所有限制**。

**卖什么**：
- 藏文排版引擎（[`tibetan-typography.md`](tibetan-typography.md)，1392 项断言的实现）+ 文化内容库 + 证书体系，打包授权
- 客户画像：文旅景区（含「冬游西藏」活动方）、博物馆/图书馆、藏文化机构、学校、亲子研学机构、藏语培训机构
- 形态：年度授权费 / 一次性定制开发费 / 内容服务费

**资金流**：机构 → 公对公/对私转账 → 你 → **开服务费/技术开发费发票**。不经过任何平台支付通道。

**优势**：客单价可达数万级（远超 C 端 1000 元/月的天花板），且**合同关系清晰、可审计**。

---

### 4.4 引擎 D · 到店导流服务费（定额版）

保留 [`merchant-system-review.md`](merchant-system-review.md) 的「自研券 + 月度对账」，但**计费口径从「核销金额 × 费率」改为「定额」**，进一步远离「支付结算」定性：

| 原设计 | 改良设计 |
|---|---|
| 核销金额 × 8% | **每核销 1 次 = 固定 X 元**；或固定月度服务费 |
| 阶梯佣金（量越大费率越高） | 固定档位，避免「按交易额抽成」的观感 |

**资金流**：用户到店 → 用**商家自己的收款码**付款（钱进商家）→ 商家扫码核销券（系统只写记录）→ 月度对账 → 商家向你付服务费 → 你开票。**你全程不碰交易资金。**

**注意**：跨商家发券 + 统一按金额抽成，仍有被认定为「变相支付结算」的观感风险，**定额化能显著降低这个风险**。

---

### 4.5 引擎 E · 持牌清算 / 升级公司（二期期权）

只在「确实要做真平台、必须线上自动分账」时才需要：

| 路线 | 做法 | 门槛 | 代价 |
|---|---|---|---|
| **第三方持牌分账** | 对接持牌支付机构的分账产品（汇付天下 / 银联商务 / MallBook / 分账链 等），资金进**持牌机构监管专户**，不经过你自有账户 | 个体户可洽谈 | 服务费；**必须尽调**：确认对接持牌机构、资金进监管户、有支付牌照背书 |
| **升级公司 + 微信支付服务商** | 注册有限公司 → 申请服务商资质 → 商家成为你旗下特约商户 → 用**原生分账** | 企业主体 | 对公账户、代理记账、企业所得税，成本显著上升；仍受 **30% 上限**、接收方须企业商户号 |

> ⚠️ 第三方分账服务商多为厂商营销口径，**务必先核实其持牌背书与资金路径**，且**微信风控始终适用**，不受任何第三方豁免。

## 5. 主体决策树（个人 / 个体户 / 公司）

```
你现在的选择，决定你能开哪几把锁：

【个人主体】
  ✅ 小程序虚拟支付（仅「工具」类目，月限额 10 万）
  ❌ 普通微信支付（不能卖实物、不能收服务费）
  ❌ 开票、签 B2B 合同
  → 只适合「先验证有没有人愿意付费」

【个体工商户】★ 推荐起步
  ✅ 小程序虚拟支付（类目更宽，无月限额）
  ✅ 普通微信支付（实物、0.6%~1%、可用经营者私卡结算）
  ✅ B2B 开票、签合同
  ✅ 导流服务费
  → 成本最低、能力够用。年认证费 300 元

【有限公司（二期，若平台化/接政府项目）】
  ✅ 以上全部，且虚拟支付无月限额
  ✅ 微信支付服务商 + 原生分账
  ✅ 政府/事业单位项目、更大开票额度
  ❌ 代价：对公账户、代理记账、企业所得税、社保
```

**建议路径**：**个人/个体户起步跑通引擎 A + B，验证有人付费后，再决定是否升级公司做引擎 E。**

## 6. 资金流总架构（两条腿，永不相交）

**铁律**：
- **C 端交易流**：用户 → 卖家的商户号（你的自营商品 = 你；商家的商品 = 商家）。**你只有在自己自营时才收款。**
- **B 端收费流**：商家/机构 → 你（服务费 / 授权费），开票。
- **永不出现**：「用户付款 → 进你的账户 → 你拆分给第三方」——这**一条**就是二清，绝对禁区。
