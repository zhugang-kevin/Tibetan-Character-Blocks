## 二、PRD 内部自相矛盾（4 条，必须先解决）

### 🔴 矛盾 1：首页地图 —— 同一份文档里既要求做又禁止做

| 出处 | 原文 |
|---|---|
| 2.1 主地图 | 「首页做成一条弯曲向上的**藤蔓**地图」「地图背景：从拉萨八廓街出发，逐渐点亮林芝、山南、日喀则、阿里的**剪影**」 |
| 第八节 不要做 | 「不要做**地图/多章节**（第二版再做）」 |

**这是同一个功能的两个相反指令。** 而且「点亮 5 个地区」需要 **5 套地区剪影插画资产**，
与现有内容量（10 关 / 8 字母 / 4 图标）严重脱节——第 3 关还没打完就点亮林芝，叙事是假的。

**建议**：做成「**曲线藤蔓路径 + 10 个节点**」（满足视觉诉求、去掉竖列列表感），
**不做地区章节解锁**。"玩方块，认藏文"现阶段的地图单位应该是**字母**，不是地区。

### 🔴 矛盾 2：雪域排行榜 —— 既要求做又禁止做

| 出处 | 原文 |
|---|---|
| 2.3 底部大平层 | 「荣誉排行 → **雪域排行榜**（全服认识藏文字母数量排名）」 |
| 第八节 不要做 | 「不要做**排行榜/社交**（分享除外）」 |

且排行榜需要**云开发数据库 + 用户身份**，与第七节「只要三个页面」的极简定位冲突。

**建议**：删除排行榜。替代方案是**本地「我的最好成绩」**（已有 `bestCombo`），沉没成本为零。

### 🔴 矛盾 3：页面数量 —— 3 个 vs 5 个

| 出处 | 原文 |
|---|---|
| 第八节 页面结构 | 「**只需要三个页面**：首页、游戏页、结算页」 |
| 5.1 唐卡碎片 | 「完整唐卡图展示在『**文化护照**』里」 |
| 5.3 证书体系 | 证书在结算页 + 可分享 |
| 现状 | 已有 **5 个页面**：index / game / result / **cert** / **passport** |

PRD 自己引用了「文化护照」这个页面，却又说只要三个页面。

**建议**：以 **5 页为准**（证书页独立才能"保存/分享"；护照页是总档案）。
把 PRD 第八节该条更正为「核心流程三页 + 档案两页」。

### 🔴 矛盾 4：登录 —— 既禁止又依赖

| 出处 | 原文 |
|---|---|
| 第八节 不要做 | 「不要做**登录/注册系统**」 |
| 7.1 三层身份 | 「L1 微信身份：`wx.login()` 静默获取 OpenID，用于跨设备同步」 |
| 7.2 数据存储 | 「云端持久化：微信云开发数据库，集合 `user_saves`，以 OpenID 为文档 ID」 |
| 7.2 | 「高价值数据（积分、印章、优惠券、付费物品）**以服务器为准**」 |

**关键区分**：`wx.login()` 静默 `openid` **没有授权弹窗、用户无感**，
严格说不算"登录系统"——它是**设备身份**。但你必须在两件事里选一件：

- **A. 纯本地**（现状）：无云开发、零成本、零合规面；换手机进度丢失。
- **B. 静默 openid + 云开发**：跨设备同步、券可绑定；月成本 0-200 元 + 需 ICP 备案。

**建议**：**MVP 走 A，把 B 的接口预留好**（`storage.js` 已经有清晰的读写边界，将来加云同步不用重写）。
理由：你已拍板"无广告"，MVP 阶段没有任何需要服务端兜底的高价值数据（券是第二阶段的事），
过早引入云端只增加备案、审核、成本和泄露面。

## 三、与既有拍板冲突（3 条，以你的最新决定为准）

### ❌ 冲突 1：广告 —— 6.1 整节作废

PRD 6.1 写了完整的激励视频广告设计（+5步 / 复活 / 翻倍 / 稀有卡），
2.2 和 2.3 还有两个「看广告」入口（八廓街集市"看广告领道具"、菩提树"看广告施肥"）。

**你在 30 分钟前刚拍板「个体工商户 + 无广告」，且理由成立**（小游戏类目免版号的前提正是"仅广告变现"，
见 `docs/business-model-v2.md`）。**二者互斥。**

**处置**：6.1 整节、以及首页所有"看广告"文案删除。
变现走商家核销 + 公益导流。**代码侧不接任何广告 SDK。**

### ❌ 冲突 2：内购 —— 技术上做不了（不是选择问题）

PRD 6.2 要 1 元礼包 / 6 元进阶包。已核验（`docs/business-model-v2.md` 第一节）：
虚拟支付的条件是「个体户**或**企业 + 已认证**小游戏** + **版号** + 软著自审报告」，
**个体户不是被主体类型挡住的，是拿不到版号**（需出版/运营单位资质）。

**处置**：6.2 整体延期到"若将来引入企业主体"。

### ❌ 冲突 3：文化卡必须点「知道了」才能继续

| 出处 | 原文 |
|---|---|
| PRD 4.3 | 「用户**必须点击『知道了』才能继续游戏**」 |
| PRD 九节验收清单 | 「文化卡有『知道了』按钮，点击后关闭，继续游戏」 |
| **你今天的反馈** | 「**每次匹配成功就跳窗需手动关**」（4 项体验问题第①条） |

**这直接回退到你上午刚要求改掉的版本。** 当前实现是：仅**首次发现**某元素时底部滑出、
**非阻塞、5.2 秒自动收起**，重复匹配只出轻提示。

**处置**：保持现状（见第六节待拍板项）。若你仍坚持 PRD 的强制关闭，
建议折中为「**首次认识该元素时**要求点掉（学习仪式感），之后不打扰」——
这恰好就是 PRD 想要的效果，但避开了"每次"这个词。

## 四、技术事实修正（4 条，照 PRD 写会出问题）

### ⚠️ 1. 「不要用 Canvas 绘制藏文字母」——现有代码违反此条

现状：`pages/result/result.js:218` 与 `pages/cert/cert.js:160` 都用
`tibText.drawTibetanWrapped()` 在 Canvas 上绘制藏文（`བཀྲ་ཤིས་བདེ་ལེགས`、证书标题）。

**问题**：Canvas 2D 的藏文渲染**不遵循** `wx.loadFontFace` 的全局字体，
若未加载真实字体，Canvas 会画成豆腐块，而页面 `<text>` 可能正常——
**同一个字在页面里正常、在导出的图片里乱码**。

**修正方案**：Canvas 绘制前显式 `ctx.font = '...px "Noto Serif Tibetan"'`，
并加一个 **`fontLoaded` 守卫**：字体未加载时，导出图里藏文改用**预渲染 PNG**（见下）。
目前 `app.js` 的 `TIBETAN_FONT_URL` 仍是占位符 → **该问题现在就是活的**。

### ⚠️ 2. 「音效用 freesound.org 免费可商用素材」——不准确

freesound.org 是**混合授权平台**：同一关键词下 CC0、CC-BY、**CC-BY-NC（禁止商用）** 混杂，
且**没有按授权筛选的保证**。商用前必须逐条核对，否则会侵权。

**修正方案**（按优先级）：
1. **继续用程序合成音效**（现状，4 个音，零版权风险）——把铜铃做得更"实"即可；
2. 需要真实乐器音时，优先 **CC0 库**（freesound 的 CC0 筛选、Pixabay Audio、Openverse 按 CC0 过滤）；
3. 藏语人声（扎西德勒 / 祝福语）**必须自己录或找授权配音**，没有可商用的免费来源。

### ⚠️ 3. 「圆角半径统一为 8px」——不要用 px

小程序里 `px` 不随屏幕缩放。现有代码统一用 `rpx`（20-32rpx），
`8px ≈ 16rpx` 在手机上**偏小**（约等于 3.8mm 半径的视觉观感）。

**修正方案**：定义**圆角 token**——小元件 `16rpx`、卡片 `24rpx`、大面板 `32rpx`，
全站引用同一组变量。品牌侧的 Logo 圆角保持 22%（那是图形比例，不是 UI 圆角）。

### ⚠️ 4. 「每关 6×8 = 48 格」——PRD 自己留了口子，保留递进

PRD 3.1 原文是「每关 6×8 网格（48 格）**，或根据关卡配置动态调整**」。
后半句允许动态。现有关卡是 6×4 → 6×8 递进，**第 1 关 24 格**是刻意的低门槛设计，
且你上午刚要求"各关牌面大小统一"——统一牌面尺寸 + 递进格数是可以并存的
（盘面居中，格数少的关卡占位更小）。

**处置**：**保留递进**。把 PRD 该条按"动态调整"理解。
