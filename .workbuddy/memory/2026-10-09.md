## 绳结断言偶发失败 —— 已根治（不是噪声）
- **根因**：第一次消除后**上方方块下落 + 顶部补充**，牌会换格；测试已按 uid 追踪绳结牌，
  但 `ropeNbs` 仍是**消除前**的格号 → 第二次按旧格号配对，配到的牌已不在绳结旁边，
  消除成功但 hp 不减（表现 hp=1）。
- **修法**：每轮按绳结牌的**当前格号**重算邻居；找不到贴着绳结的可消对子时，
  先消任意一对让盘面流动再找（补充池持续进货，必然收敛，最多 6 轮）。
- **验证**：连跑 8 次全绿 606/606（此前 3 次里挂 1 次）。

## 通用教训
- validate §6 会**扫源码字面量**：注释里写禁用 API 全名会被判为违规 → 注释改用「头像昵称类接口」措辞。
- test-h5.js 里的 `$` 是 `doc.querySelector`（CSS 选择器），模板里的 `$` 是 `getElementById`（id）
  —— 两端同名不同义，跨层调用时极易写错。
- **凡是「消除后会重排盘面」的测试，格号一律不能跨消除复用**，必须按 uid 重定位。
- **git push 已通**（见下）。沙箱默认配置里的 `credential.helper=manager`（GCM）会**卡死在等授权**；
  可用命令：
  `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null GIT_TERMINAL_PROMPT=0 git -c http.proxy=http://127.0.0.1:10809 -c http.sslBackend=openssl -c credential.helper='!gh auth git-credential' push origin main`
