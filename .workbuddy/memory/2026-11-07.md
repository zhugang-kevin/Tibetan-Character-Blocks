## D156 三次完善（真实性 / 合规一致性）

用户第三次：「继续完善、优化、完整所有的内容，确保完美性」。这次只修**说假话 / 会卡住 / 没披露**三类。

1. **不再对玩家说假话**：`show()` 从布尔改为 `{ok, reason}`（`ended/skipped/error/failed/busy/destroyed/aborted`）。
   原来「广告拉不到」和「没看完」都返回 false → 页面统一说「没看完」，
   可玩家可能连画面都没见到。现在只有 `skipped` 说没看完，`error/failed` 说「没加载出来」，
   `busy/aborted/destroyed` 静默；且拉不到**不扣次数**。
2. **切后台不再卡死**：`onHide` 调 `abort()` 收掉 `_pending`。
   不收的话回前台再点，`show()` 直接返回 busy，按钮变成「点了没反应」。
3. **隐私披露与代码对齐（合规）**：`privacy-policy-draft.md` / `privacy-mp-form.md`
   原写「无广告 SDK / 不投放广告」，与已落地广告组件冲突 —— **提交即不实陈述**。
   改为「仅微信官方广告组件 / 无第三方广告 SDK / 不获取不存储广告标识与画像 / 当前 ID 为空实际不展示」；
   未成年人条款改为**不承诺零广告**（我们识别不了年龄，承诺了就是不实）。
4. **门禁 49 → 65 项**，变异 14 → **19 全红**。
5. 顺手把两份**对外文档**里"无广告"的假陈述也修了：`release-and-monetization.md`（状态还标着"有效"，
   却写着"全仓无广告组件"）、`business-model-v2.md`（"无广告"设定）。都加了日期更正块 + 具体条目改正。

### 顺带发现的第二个"假东西"：`--fast` 是假快
`ci.py` 里 `FAST_SKIP = {'全10关通关(真点)'}` **定义了却从没被使用**——
循环里根本没有 `if name in FAST_SKIP` 分支，所以 `--fast` 一直在跑 5 分钟真点通关
（实测 `--fast` 8m11s vs 全量 8m42s，几乎一样）。
修：在 `--only` 过滤后加真正的跳过分支，并用 `--fast --only 全10关通关` 验证
输出「跳过（--fast；发布前必须跑全量）」。
**教训：声明了开关就要用一次去证明它真的生效——"有这个参数"不等于"这个参数有效"。**

### 这次最值得记的坑：假绿
变异「`abort()` 改成空实现」竟然**判绿**。原因：被 `await` 的 Promise 永不 settle 时，
Node 事件循环会空掉并**以 exit 0 退出** —— 门禁看着"全绿"，其实连一半都没跑到。
修复：① 门禁末尾加 `beforeExit` 护栏（没走到汇总就退出 = 判红）；
② abort/destroy 的断言加 60ms 竞速超时（失败报 `reason:"TIMEOUT"`，而不是静默挂死）。
**门禁必须有「我跑完了」的自证，否则"绿"可能只是进程提前死了。**

## D156 五次完善（用数据定广告位，不再往后放）
