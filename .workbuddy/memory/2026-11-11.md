### 结论先行

- 「terrible」的根因**不是审美，是机制**：微信付款确认弹窗是**白底**，而这两张是米白底 `#F6F6EF` /
  纯白底 `#FEFFFF`（四角像素采样实测）→ 在真实场景里直接消失。已通过验收的两张是深地
  `#1D1710`（灯火）/ `#5A1912`（祝福卡）。
- house style 定为：**深漆地 + 高对比主体**，主体占画面 <60%，判据 = 四角 9×9 补丁平均亮度 <140。
- 交付格式仍是 **PNG**（后台只收 PNG/JPG，GIF 会被拒）。

   塌成歧义锯齿、折叠版丢了织锦带。

### 顺带修掉的一个真 bug（validate §38.2）

主包体积 walk 原来只按**裸目录名**匹配 ignore → **所有嵌套 ignore 从来没生效过**
（`images/gift-icons`、`images/brand` 等一直被算进主包）→ 体积虚高、守卫误报超限。
新实现同时认 `relPath`（微信 packOptions 语义）与 `e.name`；并把逻辑抽成唯一实现
`calcPkgBytes(skipDirSet)`，§38.2b 反向自测**复用同一函数** —— 第一版自测抄了一份逻辑，
变异生产代码时自测照样绿（假绿），已改。判据：抽掉该嵌套 ignore 后体积**必须变大**。

### 新门禁 `validate §67`（四张全查）

PNG magic bytes → IHDR 200×200 → <200KB → **深底不变量**（四角 9×9 补丁平均亮度 <140，
零依赖解 PNG：IHDR + zlib inflate + 反 filter）→ 已排除出主包 → `scripts/build-gift-icons.py` 存在。
判据取**补丁**而非单像素：角上金饰把单像素顶到 106~149（离阈值只剩几格 → 重跑脚本假红）。

**变异 5 例全红**（每例先跑基线自证绿 → 变异判红 → 还原复绿）：
浅底哈达 → 「底色过浅」；300×300 → 「尺寸 300×300 ≠ 200×200」；16bit 312KB → 「体积 > 200KB」；
藏名卡移走 → 「缺道具图片」；去掉 `packOptions.ignore` → 「未排除出主包」（体积守卫同时翻红）。
