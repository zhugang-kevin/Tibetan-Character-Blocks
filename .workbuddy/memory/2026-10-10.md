## D67 —— TTS 服务商选型失败复盘 + 验收门禁（用户批评「太官方、忽略市场上更好的服务商」）
**用户原话**：「我发现你给我的很多信息都是太官方的，所以你还是真正忽略了市场上其他的
相关更好的服务商，就说我们现在使用的 TTS 藏文，我发现天翼的质量并不是很好的，但是你
强烈推荐我使用后，我们才发现有那么多的问题。为什么会出现那么多的错误，这个需要完美的
解决方案。」

**① 认账：我的错误不是「选错服务商」，是「把『能出声』当成了『质量合格』」。**
当时天翼是唯一能输出藏文音频的方案，我直接推荐并把整条音频管线押上去。
**更严重的是：我根本没做市场调研** —— 只测了天翼与 Edge，**从未测过 Azure / 阿里云
（它们本来就有藏语支持）**。

**② 当天没说清的口径（今天补上）**：D57 记的「75% 覆盖率」= 把 16 种文本写法 + 重试 +
参数扫描全用上之后的**最好情况**；今天冷测（单次合成、零变体）只有 **60%**（36 缺 10）。
也就是说我当时是靠「把 16 种写法全试一遍」把 60% 抬到 75%，剩下 25% 怎么试都发不出来。
**这个差异我当天完全没说明。**

**③ 市场调研（2026-10-10）**：
- **Luel Speech**（luel.ai）：专做卫藏 Uchen + 宗卡语，48kHz，双声线，Studio 可**立刻试听**、
  有 API（`@luel/speech`）。自报 CER 4.83%（真人同说话人下限 2.13%）。**首选候选**，
  但数据自报，须我方盲测。
- **Azure Speech / 阿里云语音**：**都有藏语**（1~2 声线）。**我此前从未实测** → 已进注册表。
- **讯飞/星辰实验室**：第三方盲测（10 名藏语母语评测员）：头部商业 API MOS 3.74 /
  读音准确率 **93.8%**；星辰音节级 MOS 4.28 / **97.6%**。
  ⚠️ **商用 API 整体只有约 94% 准确率 —— 不是本项目独有问题。**
- **Meta MMS-TTS**（bod/adx/khg，可离线、方言最全）：**CC-BY-NC-4.0 禁止商用** → 不可用。

**④ 完美解决方案 = 把「选服务商」变成有验收标准的门禁**（`scripts/tts_bakeoff.py`）：
- P1 覆盖率 100%（冷测口径）
- P2 变音符号敏感度：`ཨོཾ` vs `ཨོ` 时长差 ≥8% → **不需要人耳就能判定符号有没有发音**
- P3 长短元音区分：`ཀ` vs `ཀཱ`，两侧都须可闻且比值 ≥1.15
**天翼实测：P1 60%、P2 +0.0%、P3 裸 ཀ 不可闻 → 三项全挂，当场判不合格。**
（探针独立复现了我 D56–D58 逐条撞出的三个缺陷，且只要 31 秒。）
- **服务商可插拔**：新增一家只需在注册表加一条 `synthesize(text, rate)`，
  **游戏代码 / UI / 清单一行都不用改**（5 家已在册）。
- 真人录音永远优先（`form: 'recorded'` 不受服务商影响）。

**⑤ 探针自己也被证伪了两次（关键教训）**：
- **P3 第一版是假通过**：`ཀཱ/ཀ` = **22.99** 远超门槛 → 判「通过」；真相是**裸 ཀ 几乎
  没合成出来**，分母趋近 0 把比值抬上了天。**比值大 ≠ 区分得好**。已改为「两侧都须可闻」。
- **评测集加载错了**：用 Python `exec()` 执行 `voices.js`（那是 JavaScript）→ 语法报错。
  **假设文件格式 = 不验证文件格式**（今晚同族 bug 第 N 次）。改为用 node 导出 JSON。

**⑥ 门禁 §56（5 项）**：评估文档在册且覆盖 5 家（只调研「正在用的那一家」正是本次错误）/
验收工具在册且三探针齐全 / 注册表 ≥4 家（不许再被单家锁死）/
**文档必须如实标注天翼未通过验收**（不许再被推荐）/ D67 留痕。validate 1502 → **1507**（56 大类）。

**⑦ 必须用户来做（涉及账号与费用）**：① 注册 Luel，**先在 Studio 试听单个字母 ཀ**
（「能不能念孤立辅音」是生死问题）；② 同时开 Azure / 阿里云试用 Key（一并测，
避免我只测一家又下结论）；③ 真人录音并行推进（唯一 100% 正确的路线）。

**复盘**：这次的错误与之前的假绿门禁**同构** —— 我只看「有没有输出」，不看「输出对不对」，
和 `existsSync` 只看文件在不在、`indexOf` 只看调用在不在完全一样。
