### 🔴 本轮三次自我纠错（工具先自检再用，全部出结论前发现）

**① SNR 测法错误（误报 27 条「噪高」）**
- 原算法用「首段之前的静音」估底噪。实测发现：真人录音里**字与字之间的间隙**
  同样很安静，被当成了底噪 → letter_16 被算成 SNR 24.5dB（误报噪高）。
- 改正：用**全文件最安静 10% 帧**的均值（功率平均）作底噪。
  实测 letter_16：首段前法得 −77dBFS（错），最低 10% 法得 −87dBFS（对）。
- 改正后全部 SNR = **60~65 dB**（极安静），结论从「27 条不可用」翻成「31 条全合格」。
- **教训：真人录音不能用「段前静音」估底噪——语音本身的字间间隙就是低电平区。**

**② dBFS 阈值算错（`env.max()*0.06` = +53.6dBFS）**
- `env` 是**幅度域**（0..32768），峰值≈8000 → `8000*0.06 = 480`
  换算过来是 **+53.6 dBFS**（不是「峰值的 6%」那么无害）。
- 结果：字间稍高电平全被判静音 → 切出 0 段。
- 改正：`thr = max(绝对噪声门 −45dBFS, peak * 0.08)`（双约束）。
- **教训：相对比例必须以「幅度」而非「dB」解释；0.06 相对 8000 是很高的绝对电平。**

**③ 单位换算漏 ×1000（导致整份输出为 0）**
- `win` 单位是**秒**（0.02），`gap_ms/min_ms` 单位是**毫秒**（140/90）。
- 我写成 `gf = int(gap_ms / win)` = **7000 帧**（应为 7）；
  `mf = int(min_ms / win)` = **4500 帧 = 90 秒**（应为 4）
  → 段长必须 ≥90 秒才被保留 → **所有段全被丢弃 → segs 恒为 0**。
- 改正：`gf = int(gap_ms / (win*1000.0))`、`mf = int(min_ms / (win*1000.0))`。
- **教训：ms↔s 与「帧数」的换算必须带 ×1000；这个 bug 表现是「静默输出 0」而非报错，最难查。**

**排查过程记录**（供后续参考）：这个 0 输出依次排除了
①正则 `\$` 被 bash 展开（假）
② `args.only` 空串（假）
③ Python 模块缓存（假）
④ int16 平方溢出（假，astype(float64) 已正确）
→ 最后靠「手动复刻同一逻辑却得到 4段」这一对比才定位到单位换算。
**教训：手动复刻一遍最小逻辑，往往比逐行读脚本更快定位。**

### 🔴 重大自我纠正：上一轮的 A/B/C 框架是错的
**我上一轮说「峰值贴顶 → 入库后会比标准轻 4~5.5dB」，实测证明结论完全反了。**

实测 30 条真人 vs 22 条现有 TTS：
| | RMS | 峰值 | crest |
|---|---|---|---|
| 真人录音（中位） | **−17.4 dBFS** | −0.2 | **17.2 dB** |
| 现有 TTS（中位） | **−21.0 dBFS** | −7.2 | **13.8 dB** |

- **真人比 TTS 响 4.4 dB，不是轻 4~5.5 dB**。根因：我把「归一目标 −20dBFS」
  当成必须达成的目标，而实际上**不需要归一到 −20**，只需与 TTS 一致。
- **真人crest 17.2 > TTS 13.8** → 真人动态范围更宽（起音利落、收音完整），
  **教学上优于机器合成**。压缩会削掉这个优势。
- 实测**零削波**（原样峰值仅 −1.2dBFS）→ 「峰值贴顶」是**假问题**，无削波风险。

### 六方案实测（8 条抽样，真跑 ffmpeg，非推理）
| 方案 | RMS | 与TTS差 | crest |
|---|---|---|---|
| 现有 TTS 基准 | −21.0 | — | 13.3 |

| A2 中度压缩 | −24.8 | −3.8 偏轻 | 13.9 |

| D 限制器 | −16.9 | +4.1 偏响 | 14.4 |

### 决定：**A3**（acompressor threshold=-20dB:ratio=3:attack=5:release=100, volume=6dB）
三条理由：
1. **唯一落在「与 TTS 一致」区间**的方案（+2.1dB）。B/D 仍在 +3~4dB，
   每次配对那个音会「跳出来」显得突兀；A2 偏轻，浪费真人音饱满度。
2. **crest 只损失 0.7dB**（14.6→13.9）。D59 反对压缩的理由（「改变呼吸、
   句尾收弱」）针对的是 **crest 20+dB 的整句朗读**；单字辅音 crest 本就
   14~18dB，压 0.7dB 几乎无感。**D59 原则未被推翻，只是不覆盖「单字」场景。**
3. **C（重录）成本最高收益最低**：即使重录留 6dB 余量，RMS 仍约 −17，
   **照样比 TTS 响** → 解决不了真问题（响度不一致），只解决假问题（峰值贴顶）。
